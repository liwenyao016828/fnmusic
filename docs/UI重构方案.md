## 一、现状（实测数字，不凭印象）

| 项 | 实测 |
|---|---|
| 前端规模 | 组件 16,661 行（56 个 .vue）+ services/engine 6,253 行 |
| 四个组件吃掉 62% | `LibraryManager.vue` 3,480 / `ImmersivePlayer.vue` 2,397 / `SearchView.vue` 2,333 / `SourceManager.vue` 1,792 |

2. `SwipePager.vue:203` 的 `canScrollX` 已排除「横向可滚动子元素起手」的手势，`:204` 排除播放器区域 —— 手机上横滑 chip 行不会误切页。

## 二、问题清单（按「用户能感知」排序）

### P0 信息架构

1. **「音源管理」是整页，却不在导航里** —— `navItems`（`App.vue:388-399`）只有 6 项，这个页面只能靠顶栏那个音源胶囊进（`App.vue:134`）+ 一处程序化跳转（`:686`）。而那个胶囊同时还在表达「当前音源是谁」——**同一个控件干两件事，用户分不清它是状态还是入口**。
2. **工具页与内容页平级**：「日志」「设置」是排查/配置用的，却和「发现音乐」并列在同一排胶囊里；反过来「榜单管理」与「发现音乐 → 排行榜单」是一体两面（`App.vue:385` 的注释自己也这么写）。
3. **一个入口塞太多**：曲库管家里有 5 个子页 + 三步流程条 + 订阅弹窗 + 8 处联动 `downloadManager`；用户曾直接反馈「扫描缺失后，怎么没有下一步了？不修复补全吗」——**流程的下一步藏在页内**，这是展示逻辑问题，不是功能缺失。

### P1 交互与展示逻辑

4. **同一功能多套容器**：下载队列出现在 抽屉（`DownloadDrawer`）/ 面板（`DownloadQueuePanel`）/ 页面（`DownloadQueueView`）/ 曲库子页 四处，长得不一样、打开方式取决于你从哪儿点。
5. **动作位置不固定**：有的在标题右侧（`PageShell` 的 `#actions`）、有的在区块内、有的散成行内 chip。
6. **反馈有三套说法**：`components/InlineNotice.vue` + `services/userMsg.js` + 各页自写的 flash/error 变量 —— 同一件「成功/失败/进行中」在不同页面位置与措辞都不同。
7. **容器选择没有规则**：为什么下载目录是弹窗、开放接口是抽屉、音源管理是整页？用户无从预期。

### P2 视觉与代码结构

8. **没有设计令牌层**：颜色/圆角/间距/字号直接写在 16k 行模板里（`rounded-lg`/`rounded-xl`/`rounded-2xl` 混用、`text-[11px]`/`[12px]`/`[13px]` 混用）。
9. **四个 god component** 把「展示」与「业务」混在 3,000 行里，改一处要读全文件。

## 三、目标模型

### 3.1 三层容器规则（唯一判据：**这件事是「来一趟就走」还是「要待一会儿」**）

| 容器 | 用途 | 硬性要求 |
|---|---|---|
| **页面** | 常驻的内容与管理场所（发现 / 曲库 / 音源 / 账号 / 系统） | 可滑动切换、可刷新、动作区遵守 PageShell 规范 |
| **右侧抽屉** | 随手看一眼/改一下的**横切**工具（下载队列、开放接口、播放器详情） | 与下载抽屉同样的滑出交互；不遮断当前页面 |
| **全屏弹窗** | **必须做完才能走**的短流程（扫码登录、选目录、确认删除） | 一律 `max-h-[85vh] overflow-y-auto` + Esc 关闭 + 点遮罩关闭 |

> 规则不许再增加第四种；出现「放哪儿？」的争议时回到这张表。

### 3.2 信息架构提案（7 → 5）

| 现在 | 提案 | 理由 |
|---|---|---|
| 发现音乐 + 榜单管理 | **发现**（榜单作页内分段） | 二者一体两面，平级占两个胶囊不值 |
| 曲库管家（5 子页） | **曲库**（子页改页内分段，保留深链） | 层级从「二级导航」降为「同页分段」，少一次跳转 |
| 账号连接 | **账号** | 更短，手机上少占位 |
| 音源管理（隐藏页） | **音源**（进导航） | 入口必须能被发现；胶囊退回为「当前音源」状态显示 |
| 日志 + 设置 | **系统**（一页两分区，或设置进顶栏齿轮） | 工具页不该与内容页抢位置 |

### 3.3 统一四件套（所有页面只许用这四个）

- `PageShell`（已存在）→ 补齐：动作区**三级按钮**规范（主=绿实心 / 次=白底描边 / 危险=红描边）。
- `SectionCard`（新）：区块标题 + 可选动作 + 可折叠。
- `StatRow`（新）：指标行（数字 + 单位 + 变化）。
- `Feedback`（新）：`toast`（瞬时）/ `inline notice`（常驻）/ `空态`（无数据）三态统一，取代各页自写提示。

### 3.4 设计令牌

`style.css` 固化 `--ys-*`（色 / 圆角 / 间距 / 字号 / 阴影），Tailwind 层加语义类（`text-ys-sm` 等）；**新代码不许再写 `text-[11px]` 这类裸值**。
