## 0. 执行前必读

### 0.1 这是什么项目

飞牛 NAS（fnOS）上的音乐应用：Go 后端 + Vue 3 前端，打包为 fnOS 原生 `.fpk`。
**首要用途是供其他 AI / 外部程序通过 HTTP 接口调用**，人机界面是次要的。
所以「接口契约」部分（§2）优先级高于界面部分（§10）。

### 0.2 本次要验的是哪个包

| 项 | 值 |
|---|---|
| 应用名 | **曲率** |
| appname | `yinshu-ai` |
| 版本 | **2.1.0** |
| 服务端口 | **8898**（旧的「极光音乐」用 8899，两者可并存） |
| 包文件 | `yinshu-ai-2.1.0.fpk` |

> ⚠️ **执行前先核对版本，别照抄本表。** 本表会腐化，唯一权威是 manifest：
> ```bash
> grep -E '^(appname|version)=' ~/projects/music-v2/fpk-package/manifest
> ```
> 装错版本会让整份报告作废 —— 2026-09-18 那次真机验证就测的是 2.0.0，
> 而当时已发布 2.0.2，其中 2.0.1 修的正是「飞牛音乐取不到令牌（503）」，
> 于是 12 个依赖飞牛的项全被记成「阻塞」，结论对当前版本无效。

> ⚠️ 旧应用「极光音乐」(`fn-lx-player`, 8899) 是**另一个应用**，本清单**不要动它**。

### 0.3 环境

```bash

```

**三条环境铁律**（踩过坑）：

1. 浏览器访问用 **`localhost`**，不要用 `127.0.0.1`（WSL2 走 IPv6 `[::1]`）
2. `curl` 访问本机服务必须加 **`--noproxy '*'`**（环境里有 `http_proxy`，不加会走代理失败）
3. 改完后端代码后，`bash .dev/wsl-run.sh build` **只做编译检查、不生成 dev 二进制**！
   要让 dev 生效必须 `bash .dev/wsl-run.sh dev`，或手动
   `cd backend && go build -o ../.dev/fn-dev-backend .`

### 0.4 纪律（重要）

- **只读优先**：先用 `GET` 类接口验证，写操作放到最后，且先记下原始状态
- **不要删数据**：不要清空曲库、不要删音源、不要 `rm -rf`
- **不要 `pkill -f <关键字>`**：会杀掉自己的 shell。要停服务按 PID 结束
- **写结论要区分三种状态**：`通过` / `失败（附实际输出）` / `阻塞（缺什么）`

### 4.3 兼容层能力（**这一项是历史 bug 的回归测试**）


8. **`/api/catalog` 的 `data` 是 `null`** —— 接口数组在顶层 `endpoints`，这是既有设计
