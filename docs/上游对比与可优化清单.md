# 上游 fnos_music_ext 对照与我方可优化清单

- 上游仓库：https://github.com/javycoder/fnos_music_ext（权威地址；`zouclang/fnos_music_ext` 是它的 fork，非前身）
- 上游最新：**v3.1.2**（2026-11-19，VERSION=3.1.2-0，通道 stable）
- 我方基线：**上游 v2.8.0 的 `proxy/charts.py` 移植**（v2.8.0 = 2026-10-10）
- 上游架构：Python 代理接管官方 socket（`/var/run/trim_music.socket` → `trim_music_upstream.socket`），
  零入侵（不改官方二进制/nginx，官方曲库 SQLite 只读，写走官方接口）。我方是 Go 重写，形态不同，
  下面只列**可迁移的能力/修复**，不照搬实现。

  每人最多 50 份，可「同步全部用户」。v2.11.0 起按飞牛用户隔离并兼容迁移旧配置；v2.12.0 修「名称一直显示加载中」。

## 七、我方现状与差距速查

我方已有：七档音质体系、按源解析与跨源兜底、每日/热门推荐（含 LLM 层）、榜单注入（歌单卡片）、

建议优先补（按性价比）：

3. **日志导出 ZIP**（我方已有日志导出，重点看是否够用）+ 搜索链路同请求 ID 诊断
4. **VIP 行级标记 / 实际交付格式随取链落盘 / 探活 UA 一致化**（取音质量类）
5. **检查更新双通道回退 + 应用内自动更新**

| v2.12.0 取链响应的 `type/level` 作为实际交付格式 | 落盘扩展名跟随**真实容器**（魔数 → Content-Type → 兜底），AAC / WMA 不再被存成 .mp3 |

### 还没做的（有意保留）

1. **公共推荐歌单**（网易推荐 / 分类 / 精品、洛雪歌单广场只读注入 + 按用户隔离 + 展示顺序拖动）—— 产品形态问题，需要先定「注入到哪、谁能看到」，没有直接照搬。
2. **榜单 / 推荐卡片的「可播状态」标记** —— 2026-10-24 已拍板：榜单按源榜原样给满，不按可播性过滤；最多只能加一个状态标记。
3. **后台取流失败回流到前端音源健康度** —— 前端 `sourceHealth.js` 是「洛雪脚本源」级熔断，与后端「平台解析失败」不是同一维度，需要另设一套口径，不能混用。
4. **管理台那一堆运维功能**（Beta 入口集中化、批量测试面板、检查更新双通道回退、应用内自动更新、ZIP 日志导出加强）—— 与本次「听歌 / 下载 / 链路准确性」关系较弱，等有需要再做。
5. **七档音质白名单**（上游 standard/higher/exhigh/lossless/hires/jymaster/sky）—— 我方阶梯是平台实际返回的字符串（flac24bit/hires/flac/320k/192k/128k），强行套上游名字会让界面与真实交付对不上。
