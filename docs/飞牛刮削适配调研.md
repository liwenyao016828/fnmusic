# 飞牛音乐「本地刮削」适配调研

> 用户要求：搞清「飞牛音乐应用本地刮削需要什么数据才能正常显示」，再让 AI 把音乐优化为适配版本、自动扫描音乐库。
> 参考实现：**轻乐集（music-tidy）** —— 它的 changelog 里有若干条正是修这个问题的。
>
> 调研日期：2026-09-17 · 结论：**三条缺口，都是工程问题，不需要 AI 就能修**

---

## 1. 结论速览

飞牛音乐对一首歌的展示，全部来自**扫描音乐目录时读到的文件信息**。
它不读我们的数据库，只读文件本身。

| 需要什么 | 从哪来 | 我们现状 |
|---|---|---|
| 标题 / 歌手 / 专辑 | 内嵌标签（MP3 `TIT2/TPE1/TALB`；FLAC Vorbis `TITLE/ARTIST/ALBUM`） | ✅ 已写 |
| 封面 | 内嵌 `APIC`/`PICTURE`，或同目录同名图片 | ✅ 已写内嵌 |
| 时长 | 飞牛自己解码音频 | ✅ 无需处理 |
| 歌词 | 同名 `.lrc` 或内嵌 | ✅ 已写 |
| **风格（genre）** | 内嵌 `TCON` / Vorbis `GENRE` | ❌ **完全不写** |
| **能被重新扫到** | 文件 **mtime / size 有变化** | ❌ **写完不 touch** |
| **能被索引到** | 触发 `POST /shared-library/scan-all` | ❌ **从不触发** |

**按影响排序：**

1. **从不触发飞牛重扫** —— 下载完飞牛里看不到新歌（最直接的问题）
2. **写完不 touch mtime** —— 改了歌词/标签飞牛不更新
3. **不写 genre** —— 飞牛「风格」页是空的

---

## 2. 逐条说明

### 2.1 从不触发飞牛重扫（最影响体验）

飞牛音乐的曲库索引靠 `POST /shared-library/scan-all` 刷新
（见 `docs/飞牛音乐API.md` §2.4）。

我们**已经实现了** `fnos.Music.ScanLibrary()`，但——

```bash
$ grep -rn "ScanLibrary" --include=*.go .
backend/pkg/fnos/music.go:348:func (m *Music) ScanLibrary() error {   # 只有定义
```

**全仓库无人调用，也没暴露成接口** → 它是**死代码**。

**后果**：下载一首歌到音乐目录后，飞牛音乐里**不会出现**，
除非用户自己去飞牛 App 里手动点一次扫描。

**修法**：下载任务成功后（或一批结束后）调一次 `ScanLibrary()`。
注意别每首歌都调（那是全量扫描）—— 建议**一批结束调一次**，
或加个短延迟合并（debounce）。

---

### 2.2 写完标签/歌词不 touch mtime

飞牛按 **「文件路径 + mtime / size」** 做增量扫描指纹。
只写同名 `.lrc` 时，**音频文件本身完全没变**（size/mtime 都不动），
飞牛会认为「这文件没变」，于是不重新读取 —— 表现就是
**「我明明改了歌词，飞牛里还是旧的」**。

轻乐集 v1.2.18 专门修过这个：

> 飞牛音乐按「文件路径+修改时间/大小」做增量扫描指纹，只写 .lrc 附属歌词时音频
> mtime 不变，飞牛不会重读；现在每次写入歌词后自动把音频与同名附属文件
> （.lrc/封面）的修改时间刷新到当下（touch，不改动任何文件内容）

**我们现状**：`pkg/downloader` 的 `applyTags` 写完 `.lrc` 与内嵌标签后**没有任何 touch**
（仓库里的 `Touch` 都是刷我们自己的索引/监控记录，不是文件 mtime）。

**修法**：写完标签或歌词后，对音频文件与同名附属文件
（`.lrc` / 封面图）执行 `os.Chtimes(path, now, now)`。
**只改时间戳，不动内容**。

---

### 2.3 不写 genre（飞牛「风格」页会是空的）

飞牛音乐的「风格」页读的是音频**内嵌的 genre 标签**。
如果文件里没有这个标签，飞牛就归不了类。

轻乐集 v1.2.16 修过同一个问题：

> 此前整理写入内嵌标签时从不写 genre（风格只存在本应用数据库里，飞牛读不到，
> 页面上的 Blues/Dance 全是源文件自带标签）；现在整理/AI 补全写标签时同步把风格
> 写入音频内嵌 genre（flac/m4a/ogg/opus/wav/mp3 全容器 + ffmpeg 兜底）

**我们现状**（两处都没有）：

```
pkg/tags/tags.go   type Metadata struct { Title, Artist, Album, Lyric, Cover, CoverMime }
                   ↑ 结构里根本没有 Genre 字段

pkg/tags/id3v2.go  buildID3v2Tag 只写 TIT2 / TPE1 / TALB / USLT / APIC
                                                          ↑ 没有 TCON

pkg/tags/flac.go   白名单 TITLE / ARTIST / ALBUM / LYRICS / UNSYNCEDLYRICS
                                                          ↑ 没有 GENRE
```

**修法**：
1. `Metadata` 加 `Genre string`
2. ID3v2 写 `TCON` 帧；FLAC 写 `GENRE` Vorbis Comment
3. 数据来源：`pkg/tidy` 的识别结果 / 文件名里的风格代码 / AI 推断

## 3. 「AI 优化为适配版本」怎么理解

用户的原话是「ai 功能就可以把音乐优化为适配版本，并自动扫描音乐库」。
调研下来，**这件事的主体不是 AI，是工程**：

| 要做的事 | 需要 AI 吗 |
|---|---|
| 下载后触发飞牛重扫 | ❌ 纯工程，一行调用 |
| 写标签后 touch mtime | ❌ 纯工程，`os.Chtimes` |
| 写 genre 标签（值已知时） | ❌ 纯工程，加字段 + 写帧 |
| **genre 值缺失时推断** | ✅ **这才是 AI 该做的** |
| 从歌词推断情绪 / 风格 | ✅ AI 擅长 |
| 生成缺失的封面 | ✅ AI 文生图（我们 `pkg/ai` 还没接） |

**结论**：先把前三条工程缺口补上（收益最大、成本最低），
AI 只在「genre 推断」「封面生成」这类**需要判断**的地方发挥。

否则会出现「AI 写了一个 genre，但飞牛因为不重扫而看不到」这种白干。

## 4. 建议的落地顺序

> ✅ **第 1~3 项已于 2026-09-17 落地**（见 HANDOVER §11「补齐飞牛刮削的三条工程缺口」）。
> 第 4、5 项（AI 部分）**尚未开始**。

| 顺序 | 事项 | 成本 | 收益 | 状态 |
|---|---|---|---|---|
| 1 | 下载/整理完成后触发 `ScanLibrary()`（合并调用，别每首一次） | 低 | **高** —— 解决「下载了看不到」 | ✅ 已做<br>`pkg/fnos/rescan.go` 合并调度器（debounce 30s + 最小间隔 3min）<br>另加 `POST /api/fnos/rescan` 手动触发 |
| 2 | 写标签/歌词后 `os.Chtimes` touch 音频与附属文件 | 低 | **高** —— 解决「改了不更新」 | ✅ 已做<br>`pkg/tags/rescan.go` 的 `TouchForRescan`<br>接线点：`downloader.applyTags` / `tidy.TidyOne` |
| 3 | `Metadata` 加 `Genre` + 两个容器都写 | 中 | 中 —— 飞牛「风格」页有内容 | ✅ 已做<br>`Metadata.Genre` + ID3v2 `TCON` + FLAC `GENRE`<br>`SongPayload.Genre` / `tidy.Item.Genre` 也可传 |
| 4 | AI 推断缺失的 genre（接在 3 之后） | 中 | 中 —— 让 3 的数据更全 | ⬜ **未做** |
| 5 | AI 生成缺失封面 | 中 | 低（可选） | ⬜ **未做** |

> ⚠️ **前三项都不依赖 AI，已直接做掉**。第 4 项要等第 3 项落地后再接 ——
> 现在第 3 项已就位，**第 4 项可以开始了**。

### 落地后的实现要点（接手时看这里）

**① 合并调度器**（`pkg/fnos/rescan.go`）

```
debounce = 30s    一批任务结束后静默这么久才真扫
minGap   = 3min   两次实际扫描的最小间隔
```

- **最小间隔内的请求是「推迟」不是「丢弃」** —— 到点补上（有测试守着）
- 非飞牛环境（`Available()` 为 false）静默跳过，不报错
- 接线点：`pkg/downloader`（下载成功）、`pkg/api/features.go`（整理批量完成）

**② TouchForRescan**（`pkg/tags/rescan.go`）

- 推音频 + 同名附属文件（`.lrc` / `.txt` / `.jpg` / `.jpeg` / `.png` / `.webp`）
- **不存在的附属文件跳过，不凭空造**
- ⚠️ `applyTags` 里要小心 `meta.IsEmpty()` 的提前 return ——
  「只开外挂 .lrc、不开内嵌标签」时会走不到 touch（已重构修掉）

**③ genre**

- ID3v2：`TCON` 帧；FLAC：`GENRE=` Vorbis Comment
- 两个容器的**读**也要支持（否则读不回来，往返测试会挂）
- `Metadata.IsEmpty()` 要把 Genre 计入，否则「只填 genre」会被拦掉

## 5. 待确认（真机）

以下**仍未在真机上验证**，是当前最大的缺口：

1. **飞牛「风格」页到底读不读内嵌 genre** —— 推断是读（依据是轻乐集的修复方向），
   验法：给一首歌写入 `TCON=Rock` → 触发重扫 → 看「风格」页是否出现 Rock
2. **`scan-all` 在大曲库下的实际耗时** —— debounce 30s / 最小间隔 3min 是保守取值，
   真机实测后可能需要调整
3. **完整链路**：下载 → touch → 重扫 → 飞牛里正常显示，这条没跑通过
   （所有验证都在开发环境，飞牛相关代码**从未在真实 fnOS 上运行**）
