# 2026-11-01 v2.24.15 — 运行日志落盘（默认开、可关、可换目录、按大小轮转）

## 背景

用户 m00938 拍板做日志落盘（上一版报告里提的建议 1）：
「日志目前只在内存，重启即清空（log_dir 未配置）。要出问题能追查，建议在设置里配一个日志目录落盘。」

勘察发现一个真 bug：`LogDir` 字段 2026-10-26 上线时**只声明、没登记**进
`config.load()` / `config.Update()` 两处选择性合并（config.go 里那条
「⚠️ load 与 Update 是两处独立的选择性合并」的警告说的就是这种坑）。
表现：设置页保存「日志存储位置」显示成功，实际配置永远是空串，重启必丢。

## 改动

### 后端

1. **`pkg/config/config.go`**
   - `LogDir` 从 `string` 改为 `*string` 三态（nil/空串 = 没自定义 → 用默认位置），
     新增 `LogDiskEnabled *bool`（nil = 默认**开**；false = 关闭）。
   - 补登记 `load()`（重启读回）与 `Update()`（补丁合并）两处分支——这就是本次修的 bug 本体。
   - 新增读取器：`AppConfig.LogDirPath()`（用户自定义目录）、`AppConfig.LogDiskOn()`（开关）、
     `ConfigManager.EffectiveLogDir()`（**生效目录唯一判据**：关闭→空串；自定义→该目录；否则 `<数据目录>/logs`）。
   - 默认位置选数据目录而不是 NAS 音乐目录：后者要授权（`downloader.ValidateNasDir` 会拦），
     「日志该落盘」不该被授权流程堵住；数据目录本来就是应用自己的地方。
2. **`pkg/applog/sink.go`** 重写
   - `EnableFile(dir)`：同目录重复调用不再关开句柄（设置页允许反复保存同一位置）。
   - 新增**按大小轮转**：单文件 20MB 封顶，满了把 `qulv.log` 滚成 `qulv.log.1`（旧的直接丢），
     两代封顶 40MB。NAS 长期开机，不轮转迟早把卷写满。
   - 轮转后新文件开不出来（目录被删/权限变）→ 关闭落盘并清空 path，
     让日志页如实显示「未启用」，而不是假装还在写。
3. **`pkg/api/server.go`**
   - 启动恢复改走 `cfgMgr.EffectiveLogDir()`。
   - `handleLogsConfig`：GET 返回 `{enabled, log_dir, effective_dir, log_file}`；
     POST 收 `{enabled?, log_dir?}`（兼容旧 body：只传 `log_dir` 字符串字段照旧可用）。
     顺序改成**先落配置、再切实例**（反过来的话配置保存失败会出现「句柄已切走、配置还是旧的」）。
   - `GET /api/logs` 的 `hint` 按实际情况给：落盘开着时不再说「重启即清空」（旧文案是错的），
     而是「内存里留最近 N 条，同时落盘到 …（按大小自动轮转，重启不清空）」。
4. **`pkg/api/catalog.go`** 同步三个条目的描述口径（默认开、轮转、红线规则）。

### 前端

5. **`AppSettings.vue`**：「日志存储位置」输入框升级成完整的落盘控制块——
   开关（role=switch，与下载行为开关同款交互）+ 目录输入 + 「实际写入：…」回显。
   开关与目录是**两个动作**：清空目录 = 回默认位置，不再顺手把落盘关了（旧版就是这样）。
   乐观更新 + 失败回滚；操作日志写清「开/关、落到哪」。
6. **`client.js`**：`LogsAPI.saveConfig()` 支持 `{enabled}` / `{logDir}` 对象参数，
   兼容旧的字符串参数。
7. **`LogViewer.vue`**：页脚如实显示——落盘时「全部记录已落盘到 …（按 20MB 轮转，重启不清空）」，
   未开时提示可在设置里打开。
