# v2.24.8 —— 授权入口收敛为唯一的管理员共享授权

> 2026-10-31。承接同日 v2.24.7（「拆成个人授权 / 管理员共享授权两个入口」）。

## 起因

用户先问「我这个应用，只是自己用的吧，一般都是管理员自己用。」随后在「两个授权入口收敛成一个，留哪个」的追问里选了 **「只留『管理员共享授权』」**。

理由（写进代码注释，避免以后有人又加回来）：

- `pickSharedFile` 授权给**整个应用**，不按用户区分；换账号、`TRIM_UID` 变化都不受影响。
- `pickUserFile` 的授权绑定在当前登录的飞牛账号上，换个账号就得重新授权 —— 对单管理员场景只是多一个会失效的来源。

## 改动

### 后端

| 文件 | 改动 |
|---|---|
| `backend/pkg/nas/pathguard.go` | 删 `fnosUserRootsSource` / `fnosUserRootsCache` / `fnosUserSharedRoots()`；`fnosAuthorizedRoots()` 只剩「管理员共享 ∪ 系统注入」；`InvalidateFnOSRootsCache()` 只清共享缓存；`AllowedRoots()` 注释写明「2026-10-31 起不再查询个人授权」。 |
| `backend/pkg/api/fnos_auth.go` | `authStatus` 删 `user_count` / `uid`；`authorized = shared_count>0 \|\| len(fnos_roots)>0`；Hint 改单入口文案；文件头注释只列共享授权 + `openAppSetting()`。 |
| `backend/pkg/fnos/authpaths.go` | 整体重写：只留 `DataAccessiblePaths()` / `DataSharePaths()` / `splitPathList()` / `DataAccessiblePathsForTest()`。删 `UserAccessibleFolders`、`DelUserAccessibleFolder`、`CheckUserACL`、`ConvertPath`、`SystemLanguage`、`EnvUID`。 |
| `backend/pkg/fnos/openapi.go` | 删 `PlatformConfig()`（唯一调用者 `SystemLanguage()` 已删）。保留 `SharedFolders()` / `DelSharedFolder()`。 |
| `backend/pkg/nas/pathguard_roots_test.go` | 整体重写；删依赖 `fnosUserRootsSource` 的 3 条；新增 `TestFnOSAuthorizedRootsIgnoresCurrentUserUID`。 |

`AllowedRoots()` 的三条互斥分支保持不变（v2.24.7 定下的）：

1. `FN_ALLOWED_ROOTS` 已设置（**含空串**）→ 飞牛授权 ∪ 变量值（显式覆盖，开发机/非飞牛部署用）。
2. 飞牛环境（`fnos.Available()` 为真）→ **只**返回授权目录，空即 fail closed。
3. 非飞牛 → 授权 ∪ `getAvailableVolumes()` 探测卷。

### 打包

`fpk-package/config/resource` 的 `api-scope` 从 5 项精简为：

```json
["trim.file.sharedAccess"]
```

去掉 `trim.file.userAccess`、`trim.file.userAcl`、`trim.file.path`、`trim.system.getPlatformConfig` —— 对应后端调用全部删除，不再声明用不到的权限（最小权限原则）。`data-share` 与 `privilege`（`run-as: root`）不变。
