## 二、⑤ 为什么动不了（这是**需求**问题，不是实现问题）

用户原始需求是「**musicdl 和洛雪源作为歌曲下载来源**」。查代码后确认一个技术前提不成立：

- 曲率的洛雪集成 `frontend/src/engine/lx-runtime.js` **只有 `getMusicUrl`**（给一条**已知**曲目解析直链），**没有 search**。调用点在 `frontend/src/services/downloadManager.js:88` 与 `frontend/src/services/bridgeWorker.js:48`。
- 后端 `backend/pkg/bridge/bridge.go` 的 `ResolveRequest` 是 `Platform` + `Songmid`/`ID`/`Hash` —— **也是解析，不是搜索**。
- 而下载源池那一步要的是「按歌名+歌手+时长**并发找同名曲目**」= 需要**搜索**。

→ **「洛雪当池里的搜索源」按字面做不到，且与选 (a) 还是 (b) 无关**（(b) 把 LX 搬到服务端 Node 子进程，也解决不了「脚本没有 search 接口」）。

**三个选项，需要用户拍板**：

- **(a) 前端取链回传后端下载** —— 边界不动，但下载时曲率窗口得开着（与现有「订阅 → 下载到本地曲库」同一约束）。
- **(b) 搬到服务端 Node 子进程** —— 下载不依赖页面，但第三方 JS 跑在服务端，**那条边界就破了**。
- **(c) 接受需求修订**：洛雪当**兜底解析器**（曲目自己平台解析不出直链时补 URL）。落在 (a) 的形状里，基础设施已有（`bridge` + `bridgeWorker.js` 已在做这件事，只是没接进下载链路）。**这是对原始需求的修订，需用户确认。**
