## 一、设置：按分类收纳 + 入口移到侧栏左下角

**新文件 `frontend/src/services/settingsGroup.js`**：`SETTINGS_GROUPS` 七类（general 常规 / download 下载 / files 命名与文件 / storage 存储 / integration 集成 / logs 日志 / about 关于）、`settingsGroup` 持久化 ref（`PREF_KEY='settings_group'`，偏好存在 localStorage）、`setSettingsGroup(id)`（校验后写 ref + 偏好）。分类清单是**唯一出处**：侧栏展开框和设置页的过滤都读它。

**`frontend/src/App.vue`** 的入口：

- 分类列表是**普通块级元素**，展开就撑开侧栏参与布局（按钮因此会被顶上去）；没有 outside-click 收起，**只有再点一次「设置」才收**。

## 六、飞牛同步「一键清除记录」点了没反应

**根因（实测确认）**：接口和按钮都是好的 —— `GET /api/push/runs?limit=5` 返回 19 条历史，`DELETE /api/push/runs` 带不存在的 id 回 `{"code":200,"data":{"removed":0}}`，页面内 fetch 同样 200。真正的问题在 `window.confirm`：飞牛面板 / 手机 WebView 的 iframe 没有 `allow-modals`，confirm 被静默吞掉直接返回 `false`，所以点下去什么都不发生。全站既有约定就是**不用 confirm**（`LogViewer.vue` 头注释「清空：两步确认（全站现在都不用 confirm()）」）。

**改法**：`PushManager.vue` 的 `clearPushRuns` 去掉 `window.confirm`，新增 `clearArm`（`'' | 'all' | 'sel'`）+ 5 秒自动还原的 `armClear(scope)`；第一次点把按钮变成 `bg-rose-600 text-white` 的「确定清除全部 N 条？」/「确定清除选中的 N 条？」，第二次点才真正发请求，5 秒内不点自动退回。
