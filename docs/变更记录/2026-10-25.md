# 2026-10-25

## v2.21.1 更新镜像站 + 网络代理 + 更新完成提示

v2.21.0 发出去之后，用户在 NAS 上点「更新」直接失败：`Get "...releases/download/v2.21.0/yinshu-ai-2.21.0.fpk": dial tcp 20.205.243.166:443: i/o timeout`。
这条报错牵出三件事：应用由飞牛系统拉起、**读不到 shell 的 HTTP_PROXY**；公共加速镜像**不代理 api.github.com**，
所以「只加速下载」的镜像在这条链路上等于没配；更新完了应用也没有任何地方告诉用户「你已经升到哪一版」。

### 1. 代理（`backend/pkg/security`、`appupdate`、`config`）

`security.Options` 新增 `ProxyURL`，`NewSafeTransport` 改为 `newSafeTransport(opts, proxyExemptAddrs(opts), proxyFunc(opts))`：
配置里的代理**优先于** `http.ProxyFromEnvironment`，内网目标仍然直连（`proxyExemptAddrs` 把环境变量与
`Options.ProxyURL` 的主机都算进去）。`parseProxyURL` 接受 `host:port` / http / https / socks5 / socks5h，
非法返回 nil（宁可不代理，也不能拿一个坏 URL 把所有出站打挂）。`appupdate.Manager.httpClient()` 每次现取
代理值，变了就重建 client —— 改完不用重启应用。

**两个坑**：① `http.ProxyFromEnvironment` 有**进程级一次**的环境快照（`envProxyOnce`），测试里改 env 不会再生效，
「没配代理回落环境变量」这条不能在同一个测试函数里断言；② `pkill -f "fn-dev-backend -port 8900"` 会连执行它的
shell 一起杀掉（命令行字面量相同），要写 `pkill -f 'fn-dev-backend -port 890[0]'` 并且单独一条命令。

### 2. 镜像站（`backend/pkg/config/mirrors.go`、`appupdate/source.go`）

清单是有序数组 `{name,url,disabled}`，用 `*[]UpdateMirror` 存（`[]` = 「只要官方源」、缺键 = 「用默认」）。
`MirrorURL` 两种形态：前缀型（`镜像 + 官方地址`）、源型（含 `{repo}`，展开后**忽略**官方地址）。
`tryCheck` 串行逐台试，空 `tag_name` 也算失败（公共镜像常回 200 + 一段 HTML），失败原因逐条进
`CheckResult.Tried`，界面按 `✓ / ✗ 原因` 列出来。**官方源是内置兜底**，不落盘；用户要停用它就写一条
`{url:"github://official",disabled:true}` 进清单。

**踩到的真 bug**：`NormalizeUpdateMirror` 里的 scheme 检查写成 `case "http","https": return false`（写反了），
把**所有合法镜像**静默丢掉 —— 界面显示存了、实际一条都没用上。另外占位项 `github://official` 的特判原先写成
「解析后 `u.Host == ""` 才认」，而 `url.Parse("github://official")` 的 Host 是 `official`（非空），**永远走不到**，
被随后的 scheme 检查判成非法。两处都修了，并补了回归用例（`mirrors_test.go`）。

**实测**（判据 = 能否解析出 release JSON）：只有 `gh-proxy.com` 两步都代理；`ghfast.top` / `ghproxy.net` 返
`Invalid input.`、`ghproxy.cn` 返人机页、`gh-proxy.net` 返 JS 跳转、`ghps.cc` 403、`github.moeyy.xyz`/`hub.whtrys.space`
DNS 不通、`github.com.cnpmjs.org` 与 `hub.fastgit.org` 2022 年就关停了。所以默认清单只放 gh-proxy.com。

### 3. 更新完成提示（`appupdate/notice.go`）

判据是**版本号变了**（用户拍板「变化就提示」），不是「走完了应用内安装」—— 后者由独立安装脚本执行，
没法可靠回头告诉新进程「我刚装完」；而「启动时版本和上次记录不一样」一定成立，所以手动装 fpk、
应用中心升级、甚至降级都能提示。状态落数据目录的 `last_run.json`（临时文件 + rename，防写一半被杀）。
`Notice()` 只读不写；**必须等用户看到再 `AckNotice`**，否则后台轮询一调就把提示标成已读了。
`AckNotice` 还校验 `version == 当前版本`：旧页面（版本已变）点确认不能把新版本的提示作废。

### 4. 之前几项的小修

`defaultCacheTTL` 10min → 15min，前端 `AUTO_CHECK_MS = 15 分钟` 定时轮询（NAS 上应用常驻，
只在启动查一次等于永远查不到新版本）。`SourceAttempt` 补 `reason`（给界面的一句话），与 `error`（排障原文）分开。
`/api/config` 回显镜像清单时用 `UpdateMirrorsForUI()` 把内置官方源那条也带上，界面才能画「停用/启用」。

### 5. 「更新完成」弹窗不出现（两个真 bug）

浏览器实测「刷新后不弹」，但控制台 `import('/src/services/appUpdate.js')` 手动调 `ensureNotice()` 却拿到
`show:true` —— 这说明后端和 service 都没问题，问题在前端装配。查下来两处独立原因，任何一处都能让弹窗消失：

1. **响应式 ref 长在了 computed 里面**。`App.vue` 里 `showUpdateNotice` 和 `closeUpdateNotice`
   被写在 `const updateEntry = computed(() => { … })` 的**函数体内部**。computed 每次重算都会重新
   执行函数体、新建一份 `ref(null)`；`onMounted` 里的 `.then(n => showUpdateNotice.value = n)`
   赋的是闭包里那一份，模板渲染读的是 setup 上下文里那一份 —— 两份永远不同步。已提到 setup 顶层。
2. **`z-60` 在 Tailwind 里不存在**。Tailwind 3 的 z-index 只有 `z-0/10/20/30/40/50`（和 `z-auto`），
   `z-60` 不会生成任何规则，计算值是 `z-index: auto`。弹窗在 DOM 里、在视口内、元素中心点也能命中，
   但叠在侧栏抽屉（`z-[60]`/`z-[61]`）之上时被盖住 —— 人眼看到的就是「没弹出来」。已改 `z-[70]`。
   同类的坏类 `z-60` 一并修成 `z-[60]`：`UpdateModal.vue`、`DownloadDirModal.vue`、`NasDirPicker.vue`、
   `SearchView.vue:766`（发现页 toast）。这几个此前同样不生效，只是恰好没叠在别的浮层上打开过。

另外给 `appUpdate` 单例加了 `debugState()`（`notifyChecked / hasTimer / autoChecked / notice / phase / …`），
并在 `appUpdate.test.mjs` 补一条用例钉住「`ensureNotice` 命中即写 `notice`、同会话只请求一次」。

**教训**：这类问题的排查顺序应该是「元素在不在 DOM → 尺寸是否为零 → `elementFromPoint` 命中谁」，
而不是继续猜渲染。这次停在第一步（`querySelector` 没找到）就以为是渲染没出来，绕了不少弯路；
真正定位靠的是 `document.elementFromPoint(中心点)` 返回了弹窗**自己**的子节点 —— 同时说明「它在，
只是被盖住」。模板里引用未定义标识符不会让 build 失败（见 v2.20.0 那次白屏），所以 `check-tpl.mjs`
必须继续跑；而「CSS 类名根本不存在」这类问题 `check-tpl` 也抓不到，只能靠实测计算样式。

**验证**：`go build ./...`、`go test ./...` 全绿；前端 `node --test src/services/*.test.mjs` 358 项全过；
`npx vite build` 通过；`check-tpl.mjs` 0 报错 0 未绑定；浏览器实测：改 `last_run.json` 让版本变化后刷新，
弹窗出现且 `z-index=70`、中心点命中弹窗内元素；点「知道了」后后端 `notice.show=false`、`last_run.json`
写入 `acknowledged:true`；再次刷新不再弹。

**验证**：`go build ./...`、`go test ./...` 全绿（新增 `mirrors_test.go`、`notice_test.go`、`appupdate/proxy_test.go`）；
`npx vite build` 通过；`check-tpl.mjs` 三个改动组件 0 未绑定；接口矩阵实测：清单归一（补 scheme/去重/源型保留）、
恢复默认、停用官方源后 `check` 报「没有可用的更新源」、恢复后命中 `source=gh-proxy`、
`notice` 在版本变化后 `show=true` 且带 `from_version`、旧版本号 `ack` 被拒、新版本号 `ack` 后转 `show=false`
且能补上 release 说明。

## v2.21.0 补全整理重做 + 榜单满量显示 + 元数据快照

用户 m00357 的四条需求起头：①P1/P2/P3 批准照做，P4 改为「榜单显示首数可设」；
随后 m01836 / m02158 / m02159 / m02160 / m02657 / m02961 / m03647 陆续追加要求，本轮一并落地，
共 12 项新增、10 项修复、3 项优化。发布说明见 `RELEASE_NOTES.md` 顶部；本篇记内部口径与踩坑。

### 1. 榜单与在线歌单：满量显示 + 试音跨源兜底

**根因**：`backend/pkg/intercept/vchart.go` 的 `chartPlaylist` 过去对整榜跑
`i.playableOnly(ctx, ref.Source, tracks)`，后者用 `pool.ResolveMany` 逐个平台解析，**解析不出直链的直接丢弃**
—— 网易热歌榜 100 首实测只剩 36 首进榜。用户口径（m00064）：「100 首就显示 100 首，播不响的交给取音层」。

**改法**：`chartPlaylist` 去掉 `playableOnly`，改走新增的 `dedupeTracks`（`vplaylist.go`：`Normalized()` + 按
`RealID` 去重 + 跳过空 `PlatformID`/`Title`），再截断到首数；`neteasePlaylist` / 在线专辑同理，不再按可播性裁剪
（三处同一口径，`playableOnly` 保留但从榜单/歌单/专辑三条路退出）。

**缺的那半截**：显示满量以后，播不响的曲目需要别的源顶上来。`resolvePlayback`（`playback_quality.go:154`）
末尾挂 `resolvePlaybackFallback`（新文件 `backend/pkg/intercept/playback_fallback.go`）：native 失败、跨源无损分支也没救回来之后，
用 `rankedSources(ctx, title, artist, wantSec)` 找候选（只取前 `fbCandidates=3` 个非同 id 的），逐个 `ResolveLadder`。
缓存 `fbCacheTTL=30min` / 负缓存 `fbNegTTL=5min` / 上限 `fbCacheMax=1024`，总预算 `fbBudget=12s`；
⚠️ **超时的那次不写缓存**（`sctx.Done()` 分支直接 return nil），否则一次网络抖动会把「能播」钉死成「不能播」30 分钟。

### 2. 榜单显示首数（全局 + 按榜覆盖）

- `backend/pkg/config/config.go`：`AppConfig` 加 `ChartSize`（全局）与 `ChartSizes map[string]int`（按榜单 id），
  归一化走 `NormalizeChartSize`。**`normalizeChartSize` 返回 0 只代表「没填」，绝不能当「清空」用** —— 这是后面那个 bug 的伏笔。
- `backend/pkg/intercept/vplaylist.go`：新增 `chartSizeFor(chartID)`，`chartPlaylist` 用它截断。首数在**两边各算一次**是不行的，
  所以 `chartSizeFor` 是唯一入口，注释里写明理由。
- **真 bug（必看）**：`vPlaylistFor(guid, r)` 只按 `guid` 缓存 30 分钟（`vCacheTTL`），而截断发生在缓存之后 ——
  结果「改首数」要等缓存过期才生效。修法：榜单的 `cacheKey = guid + "#" + itoa(i.chartSizeFor(...))`，
  读写缓存都用 cacheKey，`pl.GUID` 仍用原 guid。同源问题在 `.dev` 联调时用户当场发现（改 60→20 没反应）。
- **前端**：`frontend/src/services/chartInject.js` 加 `chartSize`/`chartSizes` ref、`effectiveChartSize(key)`
  （优先级 = 单榜 > 全局 > `DEFAULT_CHART_SIZE`）、`setChartSize`/`setChartSizeFor`（null = 清）；
  `SearchView.vue` 加「显示首数」下拉（默认/20/30/50/100/200），卡片上点「N 首」按 `[20,30,50,100,200,0]` 循环。
  `loadConfig` 里用 `startEpoch !== writeEpoch` 与 `busy.value` 双闸，防「读回旧值盖掉用户刚点的」。

### 3. 设置保存互相覆盖（`mergeConfigPatch`）

**根因**：`backend/pkg/api/server.go` 的 `handleConfig` 里，「榜单首数」与「清空令牌」是两个独立 `if` 分支，
各自 `patch = next` 而 `next` 是 `cfgMgr.Get()` 的旧值 —— **同一次请求里后一个分支把前一个的改动整个盖掉**。
表现：「保存首数时把同请求里刚填的 token 丢了」「清空首数不生效」。
**修法**：新增 `mergeConfigPatch(next, patch)`（JSON 往返相并，patch 有内容的键覆盖 next，零值/空串不覆盖，
`json:"-"` 内部标记会被丢、调用方自己重新置位），两个分支合并成一个统一块。新增 `config_overwrite_test.go` 三例钉住。

另：`AppConfig.ChartSize/ChartSizes` 带 `omitempty`，0/空表与「没传」解码后无法区分，而 Update 是补丁语义。
加内部字段 `ChartSizeOverride bool `json:"-"``（只在 `/api/config` 流转、不落盘），overwrite 分支末尾置位。

### 4. 歌名修复（「补全整理 → 歌名修复」）

`backend/pkg/api/title_fix.go`：`GET /api/library/title-fix/scan` 扫「没歌名 / 占位词 / 歌名是文件名 / 太长 / TrackNN」，
`POST /api/library/title-fix/fix` 逐条 `suggestTitle` → `tidy.TidyOne(WriteMetadata)` → **`backup.NoteWithOld` 记旧歌名/旧歌手** → `MarkEnriched`。
`suggestTitle` 用 `ai.ParseName` + `ai.NameAppearsIn` **防幻觉**（AI 编出来的名字必须在文件名里出现过），兜底走 `tidyGuessTitle(nameparse)`。
最多 50 条/次；`s.aiReady()` 为假直接拒绝 —— 这是**修「没配 AI 也报修复成功」**：老逻辑在没有 AI 客户端时会静默回落到规则推断，
然后回 `ok:true`，用户看到「AI 修复成功」但名字没变。现在明确报「未配置 AI」。

`backend/pkg/complete/backup.go` 的 `BackupEntry` 加 `OldTitle/OldArtist`（json `old_title`/`old_artist`），
`Note` 改为转调新 `NoteWithOld` —— 修复记录列表要显示「旧 → 新」，只存新值不够撤回展示。
