### 本轮（2026-09-28 59）：**翻页后"下一页突然出现" —— 自己上一轮的优化把它弄坏了**

用户原话：「滑动结束后，下一个页面就像突然在屏幕上，加点延长或者动画过渡一下」

**根因（就是我 58 轮为了省光栅化加的那条）**
上一轮给「不是当前页的页面」加了 `content-visibility: auto` 跳过渲染。但**即将滑入的那一页也在名单里**：
它整段滑动过程都是"未渲染"状态，要等滑到位、进入浏览器的"相关区域"判定后才被**一次性渲染出来** ——
用户看到的就是"翻过去以后下一页啪地出现在屏幕上"。省下的那点光栅化，代价是翻页手感。

**改法**
- `isIdlePage()`：**只跳过隔了两页及以上的页面**。当前页 + 左右邻居始终正常渲染 →
  滑进来的那一页全程在场，视觉上跟着手指一起移动。省下来的是"离得远的两页"，那才是真正看不见的部分。
- **落位动画放顺**：缓动 `cubic-bezier(0.22, 0.61, 0.36, 1)` → **`cubic-bezier(0.22, 1, 0.36, 1)`**（≈easeOutQuint，
  尾段慢慢贴上去），时长下限 180→**220**、上限 380→**420**。

**实测（390×844、5 页全挂）**
| 检查 | 结果 |
|---|---|
| 渲染名单 | `search`(当前) `visible`、**`nas`(正滑入的邻居) `visible`**、`library/accounts/logs` `auto` ✅ |
| 落位采样（松手在 -120） | `-120 → -205 → -316 → -375 → -386 → -389 → -390`，**212ms** 内减速到位 |
| 单调性 / 有无跳变 | `monotonic: true`、无 >100px/帧 的突跳 ✅ |

### 本轮（2026-09-28 58）：**滑动流畅度专项 —— 先量后改，四件结构性降本 + 帧率探针**

用户原话：「滑动还是很卡顿，你再帮我检查一下」

**第一步：量，而不是猜**
CDP 在 NAS 的浏览器里、390×844 移动视口、**5 个页面全挂**、1.2 秒内 75 次 `touchmove`：
平均帧间隔 **16.7ms**、p95 17.6ms、最大 22ms、**0 个掉帧** —— 本机（含 5 页全挂）是满 60fps。
⇒ 结论：瓶颈在**真机的光栅化**（大图层 + 模糊滤镜），不是我这里能测出来的 JS 慢。

**第二步：四件结构性降本**
| # | 改动 | 为什么 |
|---|---|---|
| ① | 拖动位移**不再走 Vue 响应式**，rAF 里直接写 `track.style.transform`（Swiper / Embla 同款） | 以前每帧改 ref → SwipePager 重渲染 → `<slot>` 会**重新生成 vnode** → 5 个页面的整棵树每帧 diff 一遍 |
| ② | 非当前页加 `content-visibility: auto`（+`contain-intrinsic-size`） | 轨道宽 500%，不跳过渲染就是每帧为 5 页宽的图层付光栅化代价；滑进来的那页浏览器会按需渲染。⚠️ **当前页绝不能用**（它带 `contain: layout paint`，会把当前页里的 `fixed` 弹窗变成"相对页面"定位） |
| ③ | 滑动期间 `html[data-swiping]` → 关掉 `.ys-glass/.ys-player-glass` 的 `backdrop-filter` | 背景内容在动时，模糊每帧都要重算，手机上最贵的一项 |
| ④ | transform 用 **px**，不用 `calc(% + px)` | 轨道 500% 宽，百分比每帧重算 |

**第三步：给他能在真机看数字的开关**
`?fps=1` → 右上角显示实时 FPS + **最近一次滑动的最差一帧**（平均帧率好看但"某几帧掉到 100ms"才是手感杀手）。新增 `components/FpsMeter.vue`（靠监听 `html[data-swiping]` 划定统计窗口，正式界面看不到）。

**⚠️ 这轮踩的坑（靠"改完必测"抓到）**
把 `dx`/`animating` 从 ref 改成普通变量时，**漏改了一处 `animating.value = false`**（在 `begin()` 里）→
严格模式下给布尔值赋属性抛 TypeError → `begin()` 中断 → **`touchmove` 监听根本没挂上** → 整块拖拽彻底失效
（实测：拖 1 秒 transform 纹丝不动）。修完复测才通过。教训：这类"批量去响应式"的重构，改完必须实测一遍，静态检查不会报。

| 拖动路径 | `0 → -60 → -120`（跟手）✅ |

### 本轮（2026-09-28 56）：**滑动切页不卡了：页面常驻 + 数据新鲜度（TTL / 事件失效）**

用户原话：「可以了，但是卡顿的很，我感觉是每次滑之后就会触发当前页面的刷新。可以做页面数据缓存吧，提升体验，数据的及时更新你帮我想想其他项目怎么做的」

**卡顿根因（用户判断准确）**：三页滑轨里，`current` 一变，中间那页的插槽内容就换成新视图，原实例被卸载、新实例挂载 →
每个页面的 `onMounted` 重新拉一遍数据 → 切页时明显卡一下（还闪）。

**做法一：页面常驻（`components/SwipePager.vue` 重写）**
- 行 = **已经访问过的页面**（`row`），每页 `:key="id"`，按导航顺序排列；切页只改 `transform`（第 k 页 = `-k/n*100%`）。
  key 稳定 → **组件实例不重建** → 不重新请求。
- 没访问过的页面不挂载（启动仍只挂当前页）；**开始拖动时**才把左右邻居预挂上（拖到一半旁边那页已有内容）。
- 删掉 `row` 里的页面 = 卸载（暂时不做，内存里最多 5 个视图）。

**做法二：数据新鲜度（新增 `services/viewCache.js`，纯逻辑 + 9 条单测）**
把业界那几种混着用，各管一段：
| 手法 | 谁在用 | 这里怎么用 |
|---|---|---|
| **TTL + stale-while-revalidate** | SWR / React Query / TanStack Query 的默认思路 | 每视图一个 TTL（search 60s / nas 20s / library 30s / accounts 5min / logs 5s）；切回来**先显示缓存**，过期才后台静默刷、原地替换，不闪骨架屏 |
| **事件失效（invalidate）** | React Query 的 `invalidateQueries`、RTK Query 的 `invalidatesTags` | 下载完成 → `invalidate('nas','library')`（App.vue 里 watch `downloadManager.completedCount`）；标过期后**下次激活才刷**，不做无谓后台流量 |
| **首次进入照常加载** | 所有缓存方案都这样 | 不缓存首屏 |
| **`onActivated` / `onDeactivated`** | Vue `<KeepAlive>` 生态的标准用法 | 激活时按 TTL 判断要不要刷；**离开时停产** —— 日志页 5 秒轮询、发现页二维码轮询切走就停（常驻后不再有 unmount，必须显式停） |

各页接入：SearchView（激活时刷榜单/歌单/推荐）、NasExplorer（激活时只重读目录，**不重扫**）、
LibraryManager（激活时刷监控列表）、LogViewer（激活重启轮询 + 过期就刷）、AccountManager（登记 TTL）。

**真机实测（CDP 1440px，装 XHR 计数器 + 给页面根节点打标记）**

|---|---|
| 切到「本地音乐」再切回「发现音乐」 | `sameNode === true`、`data-marker` 还在 → **组件没重建** ✅ |
| 切回来时的请求数 | **1 个**（`/api/bridge/pending`，是后台桥轮询，不是页面数据）→ 页面数据零重拉 ✅ |

1. 判定只在 `pointerup` 时做一次位移比较 —— 不跟手是必然的；
2. 触屏上 Pointer Events 会被浏览器按「这是滚动」裁定并发出 `pointercancel`，而我当时把 cancel 当成"取消手势"→ 大多数时候什么都没发生（用户"只成功过一次"）；
3. **最要命的一条**：阻止条件写的是 `overflow-x` 计算值是 `auto/scroll`。但 CSS 的规矩是「只要一个轴不是 visible，另一个轴的计算值就变成 auto」，
   于是页面里所有 `overflow-y-auto` 的**竖向滚动容器**（发现页内容外面那层就是）全被判成"横滑区" → 正常区域拖也白拖。

**现在怎么做（`components/SwipePager.vue` 新增，222 行）**
- **三页滑轨**：轨道宽 300%，每页 = 视口宽，默认 `-33.3333%` 显示中间那页；拖动时给轨道加 ±dx 像素位移 → **手指下面是页面在动，旁边那页露出来**。
- **跟手**：`touchstart` 时先不拦（passive 默认不挂），`touchmove` 用 `{ passive: false }` 现挂；锁定横向后才 `preventDefault()` —— 所以浏览器不会取消手势，竖向滚动也照常。
- **轴向锁定**：10px 内定主轴，竖向 → 直接放手交还页面滚动。
- **松手判定**：拖过视口宽度 **28%** 或速度 ≥ **0.35 px/ms** 就翻；否则弹回。翻页动画 340ms `cubic-bezier(.22,.61,.36,1)`。
- **到头阻尼**：第一页往右、最后一页往左只能拉动 **35%**（橡皮筋）。
- **写 transform 用 rAF**，不经过 Vue 响应式重渲染；翻页后 `await nextTick()` 再无声复位，避免中间页闪空。
- **误触防护**：起点在真横向滚动容器（`scrollWidth > clientWidth` 才算）/ `input`/`textarea`/`select`/`range`/可编辑元素/播放器/`.swipe-no-drag` → 整个手势不接；翻页动画结束那一下的 click 被吞掉。
- 判定逻辑仍在 `services/swipeNav.js`（纯函数 + **12 条单测**：轴向锁定、阻尼、距离/速度判定、到头不翻、速度窗口、阻止条件）。

**查了 GitHub 上的现成方案**（真实数据）：`nolimits4web/swiper` ★41.9k（最全最重）、`vueuse/vueuse` ★22.4k（有 `useSwipe`）、
`pmndrs/use-gesture` ★9.6k（手势物理）、**`davidjerleke/embla-carousel` ★8.4k**（手感最好、体积最小、当天还在提交）、`zwhGithub/vue-swiper` ★581。
**结论：不引依赖** —— 它们都要求页面常驻 DOM，而这里 5 个视图都是重组件（挂载即发请求/扫目录），所以自写三页滑轨，内部做法照 Embla/use-gesture（轴向锁定、阻尼、速度判定）。想换 Embla 随时可替。
