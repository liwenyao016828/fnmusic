## ① 本地曲库：播放键改「换版本」，播放改点标题/封面

**需求（m00001）**：行内那颗「立即播放」按钮换成「替换版本」；播放不再是点按钮，
改成点歌名 / 封面那一块区域。

**前端** `frontend/src/components/NasExplorer.vue`：

- `<tr>` 去掉 `@dblclick`（单击已能播，双击会连播两次 / 播到一半重头），
  class 从 `group cursor-pointer …` 改成 `group …`。
- 标题格 `<td>`（封面 + 歌名那一格）加 `@click="playSong(song, (page-1)*pageSize+idx)"` +
  `cursor-pointer`。**只绑这一格**，不扩大到专辑 / 格式 / 体积列，避免点别的也触发播放。
- 封面 `<img>` 加 `pointer-events-none`（事件穿透给标题格）；封面 div 内加悬停三角浮层：
  `<span class="pointer-events-none absolute inset-0 … opacity-0 group-hover:opacity-100">`
  + `<Play class="h-3.5 w-3.5 fill-current text-white" />` —— 播放键撤掉后得看得出来「这块能点着播」。
- 操作列原「立即播放」（`Play` 图标）换成「换版本」：`<Replace>`（lucide v0.475 已含），
  `@click.stop="openReplaceSheet(song)"`，title「换一个版本（搜各平台版本，覆盖这个文件）」。
  `.stop` 必须留，否则点它会冒泡触发标题格的播放。
- 模板末尾挂 `<RepairCandidateSheet v-model="candidateOpen" :item="candidateItem" @replaced="onSongReplaced" />`
  —— 复用「补全整理 → 修复清单」同一套候选抽屉与替换逻辑，不另写一份。

**替换后的就地同步**（`openReplaceSheet` / `patchSongInScanCache` / `onSongReplaced`）：

- `openReplaceSheet(song)` 把本地歌映射成 RepairCandidateSheet 需要的 item
  `{path, name, title, artist, duration_sec, container:format小写, size, kbps:0, kind:'', detail:''}`。
- ⚠️ **路径可能会变**：后端 `ReplaceTrackFromCandidate` 走 `force_replace` + `dest_base`，
  新文件按真实容器换扩展名（mp3 → flac），旧路径被删、新路径见 `result.path`。
  所以不能只改 format/size，必须 `songs.value.map` 把整行换成新 path（行 `:key="song.path"`），
  否则会出现「key 没变、封面还指向已删的旧文件」。
- `onSongReplaced({item, result})` 用 `result.after.{container,size,duration_sec}` 就地 patch 行；
  `cover_url`/`cover` 清空，让 `rowCoverSrc` 按新 path 现算（后端 `/api/nas/cover?path=` 读新文件内嵌封面）；
  `patchSongInScanCache(oldPath, nextSong)` 遍历 `new Set([currentDir, ...quickDirs])` 的 `scanCacheKey(dir)`
  → `memGet` / `scanViewOfCache` / `scanCachePayload` / `memSet` 把前端内存扫描缓存里的旧条目也换掉
  （后端的扫描缓存会在下载器里失效，但前端这份 mem 缓存它管不到，切走再切回会显示旧数据）；
  最后清 `coverRetryCount`/`brokenCovers` 里的旧 path + `logInfo` + `notifyOk`。

## ② 换版本候选：加洛雪(lx)音源，musicdl 本来就在

**需求（m00428）**：用户问「替换的音乐来源是什么？加入 lx 音源还有 muscidl」。

**勘察结论**：

- 抽屉候选走 `SearchAPI.search(kw,'all',1,30)` → `GET /api/search`；
  `backend/pkg/search/aggregator.go` 的 `HandleSearch` `case "", "all":` 并跑
  `wy/tx/kg/kw` + `ExternalSearcherPlatforms()`，再 `filterAndRankSongs`。
- **musicdl 早已并进 /api/search**：`backend/pkg/search/provider.go` 的
  `MusicDLSearcher.RegisterPlatforms` 把 mg/bq/bi 注册成单平台 `Searcher`，解析侧
  `online.MusicDLResolver` 也在池里。sidecar 开着、源启用着，候选里本来就有咪咕 / 千千 / B站 —— 无需新增代码。
- **洛雪原本只在下载/探测腿**：`backend/pkg/intercept/lxsource.go` 的 `lxCandidates`
  只在 acquire 阶段用，产出的标识是 `lx:<src>`（`const lxSourcePrefix = "lx:"`），
  且**缺 Quality、缺 FileSize**（脚本不给，不编造）。解析侧 `lxresolve.go` 的 `lxResolver`
  已实现 `Platform()/Resolve/ResolveAtTier/ResolveBatch/ResolveQueries`，`ensureLxResolver` 按需注册。

**为什么另开注册表，不并进 Searcher**（`backend/pkg/search/extra.go`，新文件）：

洛雪的源 key（wy/tx/kg/mg）与原生平台**撞名**，并进 `Searcher` 会把原生搜索顶掉；
一次结果里可能多个源、标识是 `lx:<src>`；缺档位缺体积并进主搜索会改变排序。
所以新增 `ExtraSource func(ctx, keyword) []UnifiedSong` + `RegisterExtraSource/UnregisterExtraSource/
ExtraSourceNames/parseInclude/extraSourcesFor`，**默认不参与**，只有显式 `?include=lx` 才并入。
（musicdl 按平台对齐，不走这条旁路。）

**后端改动**：

- `aggregator.go` `HandleSearch`：all 分支取 `extras := extraSourcesFor(parseInclude(q.Get("include")))`，
  与平台搜索**同一个 WaitGroup** 并跑（`ctx := r.Context()`），不额外串行一轮。
- `lxsource.go` 新增 `SearchLxCandidates(ctx, keyword)` 导出包装，内部套 `lxSearchAPIBudget = 8s`
  （宿主单次超时 12s，交互式搜索等不了那么久，宁可少几条洛雪候选）。
- `main.go` 在 `if ic != nil { … SetRepair … }` 块内 `search.RegisterExtraSource("lx", ic.SearchLxCandidates)`。
  ⚠️ 必须放这里：洛雪候选要靠拦截层的解析池取链，且没拦截层时换版本接口本身就是关的
  （`/api/library/repair/*` 回 502 `available:false`）。开发机要 `QULV_TAKEOVER=1` 才会建 ic；
  接管本身失败（`等待官方 daemon 超时`）不影响 —— ic 在 Enable() 之前就建好了。
- `catalog.go` `/api/search` 补 `page_size` / `include` / `budget_ms` 参数说明与 Notes。
  ⚠️ `catalog_test.go:58` 卡 Notes ≤200 字，超了报 `GET /api/search 的 notes N 字，超过上限 200`。

**前端改动**：

- `frontend/src/api/client.js` 的 `SearchAPI.search` 加第 5、6 个可选参数 `include=''`、`budgetMs=0`，
  都只在非空/正数时才带上；`budgetMs>0` 时把该次 axios `timeout` 提到 `budgetMs+15000`
  （预算管后端等多久、timeout 管浏览器等多久，后者必须更宽）。
- `RepairCandidateSheet.vue`：`search()` 改调 `SearchAPI.search(kw,'all',1,30,'lx',12000)`；
  `platformLabel` 认 `lx:` 前缀 → 「洛雪 · 网易云 / QQ 音乐 / 酷狗 / 酷我 / 咪咕 / …」，
  `mg/bq/bi` → 咪咕 / 千千 / B站；新增本地 `qualityLabel` 对空档位返回「音质未知」
  （原来会显示成「最高音质」，洛雪候选没档位时是误导）。
  `budget_hit` 时日志追加「已到等待上限，只含先返回的平台」。

**洛雪宿主 `sidecar/lx_host/server.mjs`（两处兼容修复）**：

- `/search` 以前只认 `musicSearch`，而实测主流脚本声明的是官方 `search`
  （`Ciallo… → {wy:[musicUrl,search]}`；ikun / 星海根本不声明搜索动作）。
  改成两种动作都认（优先 musicSearch，退回 search），入参 `keyword/page/pagesize/limit` 两套键都给
  （多给不出错、少给静默返回空），结果兼容 `out.list` 与 `out.data.list`。
- 新增 `intervalToSec("03:45"/"1:02:03")`：`duration` 缺数字时退回解析 `interval`
  （官方 LX 契约里就是这个字段，主流脚本只给这个，不解析则候选恒「时长未知」、按时长接近度排序整段失效）；
  `pic` 兼容 `pic/cover/img`（img 是 Ciallo 那族字段名）。
- 更早的 v2.35.1 批次里还加了 `makeSandboxConsole()`：沙箱 console 给七个真方法 + Proxy，
  未知方法返回空函数（真脚本调 `console.group/table/time`，原来缺一个就整条取链失败还被记成「源坏了」）。

**性能坑（不是 lx 引入的，但不修抽屉就用不了）**：

`GET /api/search?source=all` 实测 50.7s、加 include=lx 60s，前端 axios 默认 30s 直接超时。
根因是 `HandleSearch` 的 all 分支 `wg.Wait()` 没有任何预算，被最慢的平台拖住。
`aggregator.go` 新增 `parseBudgetMs(raw)`（0/空/负数/非法=不限、上限 120000）
+ `snapshotResults(mu, src)`（加锁复制，防 budget 到点返回后晚到 goroutine 的 append 改写已返回数据），
all 分支用 `done := make(chan struct{}); go func(){ wg.Wait(); close(done) }()` + `select`
（`time.After(budget)`）代替裸 `wg.Wait()`；响应顶层与 data 内各加 `budget_hit`。
**缺省 0 = 老行为（等全）**，发现页搜索不受影响；只有换版本抽屉点名 `budget_ms=12000`。

## ③ 原 v2.35.1 批次（未发布，随本版一起发出）

- **播放中转 Content-Type 纠偏**：`/api/player/stream` 不再原样透传上游声明
  （实测网易云 FLAC 直链带 `audio/mpeg`，桌面 Chrome 靠嗅探能播、Safari / 移动端 WebView 按声明走就不出声）。
  `downloader.MimeForAudioHead(head)` 按魔数判容器（认不出返回空串、不猜）+ `api.streamContentType`；

  判过的类型按 URL 记进 `streamTypeCache`（256 条 / 1h TTL），拖进度条的中段 Range 复用同一类型。
