## 曲率 (yinshu-ai) v2.24.9

**「没授权却能看到整卷」的根因修复 + 桌面入口改官方统一网关微应用。**

这一版解决的是 v2.24.7/v2.24.8 之后真机上仍然存在的两个问题：应用里能看到 `/vol1`…`/vol3`、
`/media`、`/mnt` 整个卷（明明没在设置里授权），以及「授权目录」按钮在真机上从来没出现过。

### 变更

- **飞牛环境判定不再依赖 `TRIM_API_TOKEN`**（新增 `fnos.Detected()`）。原来
  `AllowedRoots()` 用 `fnos.Available()`（要求 token 非空 + socket 存在）判断「是不是飞牛环境」，
  而真机上 root 运行时系统可能没注入 token（应用中心日志里是
  `api signature verify failed, degraded: no api token granted`）→ 判成「不在飞牛」→ 走非飞牛分支
  把卷探测的 `/vol1`…`/vol3`、`/media`、`/mnt` 全并进来。**这就是「没授权却能翻整个卷」的直接原因。**
  新判据只看部署特征（`/var/run/trim_open_gateway_apiscope.socket` 或 `/var/apps/<appname>` 存在），
  与 token 无关；判错方向的代价不对称，所以宁可判成飞牛 —— 误判成飞牛的代价是 fail closed
  （点一下授权就恢复），误判成非飞牛的代价是整卷可读。
- **`/api/fnos/auth-status` 拆出 `api_available`**：`available` 改为「是不是飞牛环境」（= 该不该提示），
  `api_available` 单独表示「开放 API 现在能不能调」。于是「没有 token 但确实是飞牛」也能正常弹出
  授权提示条 —— 以前这种情况是静默的，用户根本看不到任何引导。
- **目录树去掉「存储卷」层**：自绘选择器顶部不再列出 `/vol1`、`/vol2` 这些盘位根，改为只列
  **已授权目录**（`/api/fnos/auth-status` 的 `fnos_roots`），一个都没有时显示引导行 + 「授权目录」按钮。
  `/api/nas/directories` 在飞牛环境下也只回 `AllowedRoots()`，不再试 `/vol1/Music` 之类的预设路径。
- **后端/前端去掉写死的 `/vol1/Music` 兜底**：`config.LibraryDir()` 全空时返回 `""` 而不是
  `/vol1/Music`（新增 `config.SetDefaultDirProvider`，由 `main.go` 注入「取路径守卫的第一个授权根」，
  避免底层 `pkg/config` 反向依赖 `pkg/nas`）；下载器在目录为空时返回明确的
  `ErrNoDownloadDir`（「还没有被授权访问任何目录，请先在「应用设置 → 授权目录」里授权一个音乐目录」），
  不再把文件落到一个用户从没同意过的路径。
- **桌面入口改为飞牛统一网关微应用**：`app/ui/config` 从「端口直连 iframe」
  （`protocol:http` + `port:8898` + `url:"/"`）改成官方推荐的
  `gatewayPrefix:"/app/yinshu-ai"` + `gatewaySocket:"app.sock"` + `url:"/app/yinshu-ai"`。
  **这是「授权目录」按钮能出现的前提**：JS SDK（`pickSharedFile` / `openAppSetting`）只在微应用
  形态下可用，端口直连的 iframe 里 `getHostCapabilities()` 探不到宿主，按钮永远不渲染。
  后端 `main.go` 新增 `--socket` 参数，在 `${TRIM_APPDEST}/app.sock` 上再挂一个 Unix socket
  （**TCP 8898 保留**：`service_port` 探活、队列取音落盘回调 `127.0.0.1:8898` 都依赖它，是并行不是替换）；
  `cmd/main` 启动前清残留 socket、停止时删掉。
- **网关前缀剥离**（新增 `pkg/api/gateway.go`）：真机实测网关把 `/app/<name>/**` **原样转发、不剥前缀**，
  所以后端自己剥（`stripGatewayPrefix` 包在最外层，否则 `authMiddleware` 按 `r.URL.Path` 精确匹配
  的 `publicPaths` 会把探活接口当成未知路径要求鉴权）。不带前缀的请求原样放行 → 端口直连、
  网关转发、本机自调用三种入口全部可用。
- **前端 base 路径**（新增 `services/basePath.js`）：打包时 Vite `base` 设为 `/app/yinshu-ai/`
  （站点根 `/assets` 属于 fnOS 门户自己，真机实测恒 404，不加前缀会白屏），运行期用
  `withBase()` 给所有 API URL 加前缀；`npm run dev` 仍是 `/`。
- **Unix socket 来源算「本机」**（新增 `isLocalPeer`）：走 unix socket 时 `RemoteAddr` 是 socket 路径
  而不是 IP，只认回环 IP 会让网关形态下「仅本机可见」的字段全部消失（表现为「明明授权了却一直
  提示未授权」）。能连上这个 socket 的只有本机进程，跨网段设备只能经网关（网关已校验 fnOS 会话），
  所以这样判是安全的；仍然不采信 `X-Forwarded-For`。

### 未验 / 待用户在真机确认

- 真机上「网关入口 → JS SDK 可用 → 点『授权目录』→ 弹出官方选择器 → 目录树出现」的端到端表现。
- **系统侧两个环境问题不在应用内绕过**（绕过会违反官方实现）：① 应用中心（2026-10-22）与
  `trim_open_gateway`（2026-09-15）版本不配套；② 系统只有自签 `fnOS` 证书、没有正式域名证书，
  导致开放 API token 签发/校验降级（`no api token granted`）。这两项需要用户在系统层面处理。
- `service_port=8898` 与 `micro_app=true` 均保留；`config/privilege` 仍是 `run-as root`
  （`pkg/takeover` 要 rename/重建 `/var/run/trim_music.socket`，改 package 就接管不了飞牛音乐）。
