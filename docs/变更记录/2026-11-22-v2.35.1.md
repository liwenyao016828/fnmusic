## ① 在线播放中转的 Content-Type 纠偏

**现象**：实测网易云的 FLAC 直链会带 `Content-Type: audio/mpeg`。
`backend/pkg/api/server.go` 的 `handleAudioStream` 当时是**原样透传**上游声明（为空才回落
`audio/mpeg`），于是 `/api/player/stream` 返回的是「内容是 FLAC、头写 mp3」。

**为什么不报错却危险**：桌面 Chrome 靠内容嗅探照样能播，所以开发机上一切正常；但
`canPlayType` / MSE 判定、Safari 与部分移动端 WebView 会**按声明类型走** ——
用户看到的是「明明有链接却不出声」，而每一环的日志都是正常的。

**改法**：
- `backend/pkg/downloader/downloader.go` 新增 `MimeForAudioHead(head []byte) string`：
  复用下载落地那套 `detectAudioExtByMagic` 的判据，把容器映射成标准 MIME
  （flac→`audio/flac`、mp3→`audio/mpeg`、aac/m4a/ogg/wav/wma 同理），**认不出来返回空串**
  —— 不猜，让调用方沿用上游声明。
- `backend/pkg/api/server.go` 新增 `streamContentType(upstreamCT, head)`：
  魔数认得出就用魔数，认不出才沿用上游声明，都空才回落 `audio/mpeg`。
- `handleAudioStream` 在 `streamClient.Do` 之后先 peek 开头 `headPeek = 512` 字节
  （`io.ReadFull`，容忍 `ErrUnexpectedEOF`/`EOF`），再把 head 原样写回响应体
  —— 读头回写最容易丢字节，这里一个字节都不能少。
- ⚠️ **只在 `startsAtZero` 时嗅探**：判据是「没有 Range 头」或「`Content-Range` 以 `bytes 0-` 开头」。
  Range 从中间起时开头那几个字节是音频流中段，魔数判断必然误判。
- `handlePlayerCheck` 改用同一个 `streamContentType`，让预检回报的类型与中转一致。

**补一层「拖动进度条」的边界**：拖进度条会让同一个 URL 再来一串 Range 中段请求，
那些响应的开头是音频流中段，没法再判魔数 —— 结果是同一个文件「头一段 audio/flac、
拖一下变 audio/mpeg」。所以加了一个**纯加速用**的包级缓存（`streamTypeCache`：
256 条上限、1 小时 TTL、键是完整 URL 含 vkey）：从文件开头判出类型时记下来，
中段请求直接复用；判不出来才退回上游声明。缓存满了先清过期项、再满就整表丢掉
（宁可退化成「沿用上游声明」，不值得为它做 LRU）。`handlePlayerCheck` 拿的也是
文件开头，判出来的类型一并写进缓存 —— 避免「预检说 flac、真播又说 mp3」。

**测试**：新增 `backend/pkg/api/audio_stream_test.go`
（`TestStreamContentTypePrefersMagic` 6 例、`TestHandleAudioStreamCorrectsContentType`
逐字节比对 5004 字节、`TestHandleAudioStreamKeepsUpstreamTypeForMidRange` 断言「没判过的 URL
中段仍沿用上游」、`TestHandleAudioStreamReusesTypeForMidRangeAfterProbe` 断言「判过之后
中段复用同一类型」、`TestStreamTypeCacheIsPerURL` 断言缓存不串 URL），
`backend/pkg/downloader/downloader_test.go` 新增 `TestMimeForAudioHead` 7 例。
注意两处坑：`pkg/api` 已有 `itoa`（`nas_delete.go:188`）故测试里用 `strconv.Itoa`；

## ② 洛雪宿主沙箱的 console 补齐

**现象**：真机日志里 `_new_URL_ikun音源_公益__v24.js` 报 `console.group is not a function`，
整条取链失败，而错误被记成「解析响应数据失败」—— **看起来像「这个源坏了」**。

**根因**：`sidecar/lx_host/server.mjs` 给脚本的沙箱只提供了
`console: { log() {}, warn() {}, error() {} }` 三个方法，而真脚本把 console 当浏览器的用。

**改法**：新增 `makeSandboxConsole()` —— 七个真方法（log/info/warn/error/debug/trace 及外层
Proxy）**, 未知方法一律返回空函数而不是 `undefined`**（`get` 里对字符串键返回 `() => {}`）。
宁可让某个没见过的调试方法静默无效，也不能让整条取链因为一行日志挂掉。

**测试**：`backend/pkg/lxnode/lxnode_test.go` 新增
`TestSandboxConsoleSupportsBrowserMethods`：真 node + 真宿主（端口 18946），夹具脚本把
`group/info/debug/table/groupCollapsed/log/groupEnd/time/timeEnd/count/assert/trace/dir`
全调一遍再交直链，断言能拿到 URL。
