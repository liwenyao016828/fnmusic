**一、`h-screen` 是手机上的隐形 bug，不是风格问题**

手机浏览器地址栏会吃掉 `100vh` 的一部分，而根容器是 `flex flex-col h-screen`
⇒ **底部播放条被推到可视区之外**（露一半或整条看不见）。改用 `.app-viewport`（先 `100vh` 兜底老 WebView，
再 `100dvh` 覆盖）。`w-screen` 一并换 `w-full` —— iOS 上 `100vw` 含滚动条宽度、会横向溢出。

**二、顶栏三个入口在手机上点不到（460px 挤进 68px 单行）**

原顶栏是 `h-[68px] … whitespace-nowrap overflow-hidden` 的单行：品牌 + 5 个导航项 + 右侧 3 个入口，
390px 屏宽下实际内容 460px+ ⇒ 被 `overflow-hidden` 裁掉，**「音源 / 开放接口 / 打开播放器」三个入口
在手机上完全不可达**（裁掉的部分既不可见也不可滚动）。

**解决方式：手机上去掉文字、只留图标 —— 不是折两行。**
（第一版我折成了两行，用户一句否掉：「顶部菜单显示不全的话，可以不显示文字啊，**不要两行**」。）
现在：导航项手机只显示 14px 图标（`p-2.5` ⇒ 34px 一个，名称靠 `sm:inline` 才出现）、
音源按钮文字截到 `max-w-[56px]`、开放接口 / 打开播放器本来就只在手机显示图标，
导航容器挂 `min-w-0 overflow-x-auto no-scrollbar` —— 极端窄屏时它自己横向滚动，**任何入口都不许被裁掉**。
图标类按钮补了 `:title` + `:aria-label`；顺带删掉了 navItems 里已经没人用的 `shortName` 字段。

**桌面端逐字核对过，没有任何改动**（用户那条指令的原话：「手机适配为图标，**电脑端不变，就按之前**」）：
`sm:` 以上仍是 `h-[68px]` / `gap-7` / `px-8` / 图标 + 名称 / `whitespace-nowrap` / `overflow-hidden`。

**❌ 顺带修掉一个我自己引入的位置错**：两行方案里把「右侧入口组」挪到了导航**前面**，
改回单行时忘了挪回去 —— `ml-auto` 于是把导航胶囊顶到了屏幕最右边缘（本该是品牌 → 导航 → 右侧入口）。
用户一眼看出「位置不对」。DOM 顺序已恢复，并在 §3.3.4 里写死了这个顺序。

**三、刘海安全区：`viewport-fit=cover` 早就开了，但没人用**

`index.html` 的 viewport 一直带着 `viewport-fit=cover`，可是没有任何元素吃 `env(safe-area-inset-*)`
⇒ 内容顶到状态栏 / 底部横条底下。现在顶栏、播放条、沉浸页上下栏、两个抽屉都吃安全区。

⚠️ **踩到的坑**：`.pt-safe` 与 `pt-2` 是同一个 CSS 属性，而自定义工具类排在核心工具类**之后**

**七、鉴权按「来源地址」分三层（默认不再完全放开）**

**八、补全任务可以停止（体检清单第六条：长耗时任务收不到取消信号）**

体检报告里这条的原话是「`context` 只出现在 6 个文件」。真挖下去，缺的**不是**「到处传 ctx」——
优雅关停早就有了（`main.go` 已经 `signal.Notify(SIGINT/SIGTERM)` → `StopScheduler()` → `httpServer.Shutdown(10s)`，
超时才 `Close()`）。真正的缺口是三处：

| 缺口 | 表现 | 本轮 |
|---|---|---|
| **补全后台任务不可取消** | `completeJob` 喂的是 `context.Background()`。一批最多 200 首、每首两次外网请求 + 改文件，分钟级；再点一次会被 409「上一次补全还在跑」挡回 —— **没有任何叫停方式**，而它正在改用户的音频文件 | ✅ 做 |
| 同步长任务不理会客户端断开 | `POST /api/tidy`（≤500 首，同步写）、`/api/nas/songs` 递归枚举、`/api/library/index` 扫描 | 本轮只记入本节 |
| `pkg/search` 公共 API 无 ctx | `Search`/`FetchLyric` 等约 15 个函数、`doHTTP` 单出口 10 个调用点 | ❌ 不做（理由见下） |

**为什么 `pkg/search` 不加 ctx**：每个搜索请求本来就有自己的超时，出口又有全局节流器
（`throttle.go` 的预约式时间片）保证速率。加 ctx 只能省掉「取消后剩下的几秒」，
却要动 15 个函数签名与 10 个调用点，把一处简单的 HTTP 出口改成「每个调用方都得记得传 ctx」。
**有界超时 + 全局节流已经覆盖了同一个风险**，收益是秒级、代价是整条链路的可读性 —— 不值。

改动（5 个文件 + 2 个新测试文件）：

| 文件 | 改动 |
|---|---|
| `backend/pkg/complete/complete.go` | `ItemResult.Cancelled`（**必须与 `NoMatch`/`Failed` 分开**：那两个是关于这首歌的结论，这个只是关于任务的结论）、`Summary.Cancelled`、`Plan.Cancelled`（解析阶段没轮到的曲目数）；`Resolve`/`Execute` 派发循环开头 `if ctx.Err() != nil { break }`，末尾把「没轮到的」记进 `Cancelled`；`writeOne` 一进来就挡住已停止的任务（**一个字节都不碰** —— 并发池里已派发的几首是在 stop 之后才轮到的） |
| `backend/pkg/api/library_complete.go` | `completeJobState` 加 `ctx`/`cancel`/`cancelled`；`start()` 改为**返回可取消的 ctx**（叫停口子只有这里能掌握）；新增 `cancelRun()`（没在跑如实回 false）；新增 `HandleLibraryCompleteCancel`（非 POST → 405）；`runCompleteJob` 收 ctx；收尾时把「解析阶段没轮到的」补进 `summary.Total/Cancelled`，并按**实际处理数**回填进度（否则 done 会停在 3/3，看起来像全处理完了）；被停止时打一条日志 |

| `frontend/src/components/LibraryManager.vue` | 进度行加「停止」按钮（只在 running 且未停止时出现）；标题区分「正在停止…／上次补全被停止」；汇总行单列「N 首没处理（任务被停止）」；轮询收尾话术区分「补全完成」与「补全已停止」 |

**停止的语义（写死在代码注释里）**：不再派发新曲目；已写入的保留（要回退用撤销，备份清单还在）；
正在写的那一首会写完（写到一半中断会留下半个标签块，比不写更糟）。没在跑时**如实回**「没有正在跑的补全任务」——
回一句「已停止」会让用户以为停了什么。

真机冒烟（dev `:8900`，`POST /api/library/complete` 起任务后 1.2 秒停）：

```
POST /api/library/complete {"fields":["lyric","cover"],"limit":3}  → 202「已开始补全 3 首」
（等 1.2s）
POST /api/library/complete/cancel  → 200 {"running":true,"done":0,"total":3,"cancelled":true}
                                     message「正在停止：不再开始新的曲目，已写入的会保留。」
（等 5s）
GET  /api/library/complete         → running:false cancelled:true
                                     summary: total 3 · cancelled 3 · results 0 · no_match 0 · failed 0
POST /api/library/complete/cancel  → 200「没有正在跑的补全任务」（空跑时，不假装成功）
GET  /api/library/complete/cancel  → 405「只支持 POST」
日志： [COMPLETE] 收到停止请求：不再派发新曲目，已写入的保留（可用撤销回退）
       [COMPLETE] 任务已停止：已处理 0 首，未处理 3 首（已写入的保留，可用撤销回退）
```

**要盯的断言**：`cancelled` 3 首、`no_match` 0、`failed` 0 —— 被停止**没有被算成「没搜到」**。
（「停一下之后汇总里 180 首没搜到」那种假象，就是这批字段最容易退化的地方。）

新用例 **10 个**（`pkg/complete/cancel_test.go` 3 个 + `pkg/api/library_complete_cancel_test.go` 7 个）：
已取消的 ctx 下 `Resolve` 不产出计划项且记 `Cancelled`；`Execute` 不产生任何结果、也不混进 no_match/failed/matched；
三个 `cancelled` 字段的 JSON 名固定（`Plan` 的 0 值必须 omitempty，`Summary` 的必须出现）；
`cancelRun` 空跑返回 false 且不点亮标记；在跑返回 true 且真的取消 ctx；收尾后返回 false 但保留「被停止」标记；
`start` 不继承上一轮的标记；接口空跑 200 如实说明；在跑 200 且 ctx 被取消；GET → 405。

**九、静默失败收口（体检清单第七条）**


三条结论：

1. 体检报的 aggregator 那 10 处，**第三条（平台故障可观测）就已经统一收口了** ——
   记录点挂在 `doHTTP`（`pkg/search` 唯一的出站出口，`throttle.go:100/110/114`），
   所以这个包以后新增端点，**失败不需要记得注册**也会被计数 + 写日志。
2. 「出错还在干活却不留痕」现在是 **0** 块。（`swallowed` 从 94 降到 0 的过程里，
   绝大多数是把「已经交给 HTTP 层 / 已经写进结果对象」认出来 —— 假阳性，不是真缺口。）
3. 真正要修的是**把「空」当成「结果」**的四处：

| 位置 | 原来 | 现在 |
|---|---|---|
| `pkg/charts/charts.go` 酷狗榜单详情 | 翻页时 `NewRequest` / `Do` / `ReadAll` / `Unmarshal` 任一失败就 `break`，然后照样回 200 + `track_count: 0`。**「这个榜是空的」和「根本没拉到」长得一模一样** | 拆出 `kugouChartPage`：第 1 页失败 → 502 + 理由 + 日志；第 2/3 页失败 → 保留已拿到的页 + 一条 warn（说清少了一页）；上游**真的**回空列表 → 200（正常结果，不报警） |
| `pkg/charts/charts.go` 酷我榜单 / 歌单 | 主接口失败被几层 `if err == nil` 吞掉，兜底搜索 `searchKuwoSongs` 又**返回 nil** —— 界面上就是「这个榜 / 歌单 0 首歌」 | `searchKuwoSongs` 改为返回 error，调用方拿到失败即 502；主接口没拿到曲目时先记一条「停在「哪一步」」的 warn，再走兜底 |
| `pkg/library/index.go` 索引加载 | 文件损坏 → 静默从空库开始；而且**下一次 Save 会把坏文件覆盖掉**，事后无从查证 | 损坏 → 留档成 `library_index.json.bad-<时间>` + warn；读失败（非「不存在」）→ warn；「不存在」= 首启，保持安静 |
| `pkg/nas/pathguard.go` 飞牛共享目录 | `fnos.SharedFolders()` 失败 → `roots = nil` 静默缓存 30 秒，之后所有飞牛目录都判成「不在允许访问的范围内」，真因（接口不可用 / 令牌失效）一个字都没有 | 真去拉了但失败 → warn（30 秒缓存天然限流，不会刷屏）；飞牛不可用（没令牌 / 没 socket）是**正常**情况，仍然安静 |

为了让「上游失败」的路径**可测**，三处内联的上游地址提成了包级变量
（`kugouRankInfoURL` / `kuwoSearchURL` / `kuwoBangURL`），默认值就是线上地址，运行时行为不变。

新用例 **12 个**：`pkg/charts/chart_failure_test.go` 6 个（第 1 页失败 → 502 + 日志、
第 2 页失败 → 保留已有页 + warn、上游真回空 → 200 且不记日志、兜底搜索失败 → 返回错误、
兜底搜索正常解析、主接口失败 → 日志写明停在哪一步）、

**十、两套目录遍历合并成一份规则（体检清单第八条）**

体检说「`pkg/library` 的 `WalkDir` 与 `pkg/nas` 的 `Walk` 是两套」—— 是的，而且**规则还不一样**：
索引侧有排除目录（`.tidy_trash`/`@eaDir`/`#recycle`…）、深度上限、软链接 realpath 剪枝、协作式取消、审计计数；
浏览侧只跳「.」开头的目录，硬编码 1000 首，**没有**深度上限、**没有**环保护，
而且「读到上限了」和「某个目录读不了」**都不告诉调用方** —— 同一棵树，
曲库索引和 NAS 浏览能给出不同答案，界面上那句「已加载 1000 首」看起来就是这个目录的全部。

做法：新建 `backend/pkg/dirwalk`（让两侧都依赖它，避免 `nas → library` 这种语义倒挂），
把遍历规则搬进去；`pkg/library` 退成薄适配层（`scanner.go` 201 → **75** 行），`pkg/nas:ScanSongs` 改调它。

| `pkg/dirwalk` 的契约 | 说明 |
|---|---|
| `Walk(roots, Options) ([]File, Stats)` | `Options{MaxDepth, MaxAudio, ExcludeDirs, IncludeHidden, AcceptFile, ShouldStop, OnProgress}`，零值可用 |
| `DefaultMaxDepth = 12`／`DefaultExcludeDirs` | 排除 `.tidy_trash`/`.trash`/`@eaDir`/`#recycle`/`.recycle`/`$RECYCLE.BIN`/`System Volume Information`/`.git`/`node_modules`（群晖每个目录都带一份 `@eaDir`，不排除就会被逐层翻） |
| `Stats` | `files_total`/`audio_total`/`dirs_visited`/`inaccessible`/`depth_truncated`/`skipped`/`limit_hit`/`stopped`/`missing_roots`/`warnings`/`elapsed_ms` —— JSON 键**沿用 `pkg/library.Audit` 的口径**，两个接口的字段含义不会各说一套 |
| `Stats.Complete()` | 无缺失根 && 没有读不了的目录 && 没被深度截断 && 没到数量上限 && 没被取消 |

两侧的改动都是「接上」，不是重写：

- **索引侧**（`pkg/library/scanner.go`）：只做映射（`dirwalk.File` → `Entry`，`Stats` → `Audit`），
  `Audit` 结构与接口 JSON **一字不变**（四家调用方与既有 6 个用例无感）。
- **浏览侧**（`pkg/nas/scanner.go`）：响应新增 `truncated` 与 `warnings`（首次枚举另带 `audit`）；
  越权/成环的软链接文件仍然**不暴露给前端**，但现在计入 `skipped` —— 是「看得见的跳过」，不是静默丢弃。
  `scancache.go` 的缓存条目也存这两个字段：**命中缓存也必须如实说「这份列表是被上限截断的」**，
  否则缓存会把一次截断洗成「完整」。
- **接口目录**：`GET /api/nas/songs` 补 Notes，写明与 `/api/library/index` 是同一套枚举规则、截断会如实报。
- **界面**（`NasExplorer.vue`）：「(已加载 N 首歌曲)」后面多一行琥珀色的
  `· 还有没列出来的（结果被截断）`，悬停给出具体原因（就是后端那条 warning）。

新用例 **15 个**：`pkg/dirwalk/walk_test.go` 12 个（文件/音频计数、默认与额外排除目录、隐藏目录与隐藏根、
深度上限、数量上限、软链接环终止、缺失根、主动取消、`AcceptFile` 跳过并计数、读不了的目录、进度回调、空 roots）、
