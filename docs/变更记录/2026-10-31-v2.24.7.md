# v2.24.7 —— 按官方权限模型收紧目录访问，拆分两类授权入口

日期：2026-10-31
版本：2.24.7（上一版 2.24.6）

## 背景

用户指出两件事（2026-10-31）：

1. **普通用户调用 `pickUserFile` 失败时自动回退到 `pickSharedFile`** —— 官方文档明确
   `pickSharedFile` / `authorizeSharedFile` 仅管理员可用，普通用户直调会得到
   `code:1 "仅管理员可进行此操作"`。自动 fallback 把这个报错藏起来了。
2. **飞牛环境下 `AllowedRoots()` 仍会自动并入探测卷**（`/vol1`…`/vol16`、`/media`、`/mnt`）
   —— 官方模型是「没授权 = 看不见」，自动放行整卷等于绕过用户在应用设置里的授权动作，
   也让「只授权一个子目录」实际变成「整个卷可读」。

同时参考了 GitHub 上 `fnmusic-ext`（javycoder/fnos_music_ext，haonanren118、
superxyline 的 fork 一致）：它只申请 `trim.file.userAccess` 一个 scope，证明个人授权
就够用；曲率此前多给了 `sharedAccess` + fallback，超出需要。

## 改动

### 后端

- `backend/pkg/nas/pathguard.go`
  - 新增 `fnosAvailableSource`（默认 `fnos.Available`，测试可替换）。
  - `AllowedRoots()` 改为三条互斥分支：
    ① `FN_ALLOWED_ROOTS` 已设置（含空串）→ 飞牛授权 ∪ 变量值（显式覆盖）；
    ② 飞牛环境（令牌 + socket 可用）→ **只** 返回飞牛授权目录，没有就是空（fail closed）；
    ③ 非飞牛环境 → 飞牛授权 ∪ 探测卷（开发机还能选目录）。
  - 新增导出函数 `FnOSAuthorizedRoots()`：飞牛授权目录的归一化并集，不含探测卷、
    不受 `FN_ALLOWED_ROOTS` 影响，给 api 层判断「到底有没有授权」用。
- `backend/pkg/api/fnos_auth.go`
  - `authStatus.FnosRoots` 改为直接读 `nas.FnOSAuthorizedRoots()`；删掉
    `fnosRootsOnly` / `builtinVolumePrefixes`（旧口径会把「管理员授权了整个 /vol1」
    误判成内置卷）。
  - `HandleFnosAuthRefresh` 的 `authorized` 只看飞牛授权这一份（开发机探测卷不再
    被误报成已授权）。
  - 未授权 Hint 文案改为引导两个明确入口：「个人授权」/「管理员共享授权」。
- 新增测试（`pathguard_roots_test.go`）：飞牛环境未授权 = 空、飞牛环境不混探测卷、
  非飞牛退回探测卷、环境变量在飞牛环境也生效、`FnOSAuthorizedRoots` 不吃掉整卷授权。

### 前端

- `frontend/src/services/trimHost.js`
  - `pickDirectory()`（个人授权，`pickUserFile`）**移除**到 `pickSharedFile` 的自动
    回退；取消/超时/不支持都如实返回。
  - `pickSharedDirectory()` 注释与默认标题明确「管理员专属入口」，与个人入口分开。
- `frontend/src/components/FnosAuthNotice.vue`
  - 授权按钮拆成两个：「个人授权」（琥珀色主按钮）与「管理员共享授权」（次按钮），
    共用 `grantWith()` 收尾（刷新状态、反馈、通知父级）。
  - 默认提示文案同步两个入口的说明。

### 打包 / 文档

- 版本四处同步：`server.go CurrentVersion`、`fpk-package/manifest`、
  `RELEASE_NOTES.md`、`HANDOVER.md`。

## 验证

- `go build ./...` / `go test ./...`（backend）全绿。
- 前端 `node --test` 503/503；`vite build` 通过。

## 遗留

- `fpk-package/config/resource` 仍保留 `sharedAccess` scope（管理员共享授权入口需要它）；
  如果最终决定只做个人授权，可以像 fnmusic-ext 一样精简成 `["trim.file.userAccess"]`，
  届时「管理员共享授权」按钮也要移除。
