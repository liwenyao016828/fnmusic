## 曲率 (yinshu-ai) v2.24.14

**全链路日志补全：播放/下载/订阅/补全/推送/音源都留痕，出问题能追。**

承接用户口径：「补上播放日志，还有其他功能的日志也补上……审查整个项目代码，把运行日志、任务日志、
操作日志都记录下来，记录下载成功/失败及来源」。此前网页端播放**成功时只写一条「播放 歌名」**，
取链的音源、平台、实际档位、直链域名、是否跨源换源、耗时全在浏览器 console 里；浏览器一关就没了，
日志页只能看到失败那一条。本轮把三类日志按「能追查」重做。

### 变更

- **新增 `backend/pkg/applog/safe.go` 的 `HostOf(url)`**：日志里出现的下载/播放地址**只保留域名**
  （去端口、去路径、去查询串），解析失败返回「(地址无法解析)」而**不回退原 URL** —— QQ/网易的直链带
  `vkey`/签名，整条写进日志等于把播放凭据落盘。所有新增的地址日志一律走它。
- **后端下载任务（`pkg/backenddl/queue.go`）**：入队/去重/跳过/整队暂停、任务开始（第几次尝试、目标档位、
  平台）、成功（实际档位、来源渠道、文件大小、耗时、落盘路径）、失败（原因链、次数、耗时）各记一条；
  批量动作回报影响条数。
- **取音过程（`pkg/backenddl/fetch.go`）**：记录候选清单、逐条尝试与失败原因、最终获胜来源与域名；
  FLAC 坏流降档、平台缺档降档都写清「点名要的是什么、实际给的是什么」；全部失败时汇总所有候选。
- **下载器（`pkg/downloader/downloader.go`）**：统一「开始 / 完成 / 失败 / already_exists」日志外壳，
  含路径、档位、格式、大小、来源、域名、耗时 —— 已在盘上直接复用不再和真下载混为一谈。
- **订阅与后台（`pkg/monitor/http.go`、`pkg/complete/complete.go`、`pkg/push/runner.go`）**：监控每轮
  开始/汇总/失败/候选换源；补全整理起止、写入汇总、停止、备份失败、失败摘要；推送触发方式、
  耗时、命中/新增/已存在/缺失/本地命中/过期移除、封面与扫描警告。
- **音源与队列接口（`pkg/sources/manager.go`、`pkg/downloadqueue/store.go`、`pkg/api/backend_download.go`）**：
  音源池增删导入（导入地址同样只记域名）、队列异常、接口 500 与动作拒绝。
- **洛雪宿主日志进日志页（`pkg/lxnode/lxnode.go`）**：宿主 `logf` 之前只写终端，改走 `log.Printf`
  进入 applog —— 用户反馈的「点播放没反应」有一半答案在宿主里。
- **网页端播放（`frontend/src/App.vue`）**：取链成功记 `播放取链`（音源 · 平台 · 档位 · 直链域名）；
  原平台取不到而跨平台换源成功时单独记 `跨源换源`（`平台A → 平台B：《曲名》— 歌手` + 域名），
  放错歌时靠这条定位；NAS 本地播放、播放全部各记一条；失败日志补上目标档位、待尝试的换源平台、
  歌曲 id；新增 `urlHostOf()` 同样只取域名。
- **下载队列前端（`frontend/src/services/downloadManager.js`）**：任务第一次进入 `success`/`failed`
  终态时去重记一条（轮询会反复读到同一状态，不去重会刷屏）；成功含实际档位、来源平台、落盘路径，
  失败含原因与尝试次数。
- **其余关键操作**：音源切换/导入/删除（`SourceManager.vue`）、曲库体检与修复（`LibraryHealthCard.vue`）、
  补全整理预览/写入/停止/去重（`TidyView.vue`）、订阅开启与补下载（`services/pushEngine.js`）、
  飞牛重扫（`FnosSyncPanel.vue`）。

### 说明

- 日志里**不含**带签名的完整直链；歌单链接只记用户自己粘贴的那条（不含平台签名）。
- `pkg/intercept` / `online` / `library` / `charts` / `account` / `nas` / `fnos` / `appupdate` 未逐条扩展：
  intercept 主干已有日志，online 的取链失败已被 fetch 的候选日志覆盖，其余多为低频只读接口。

### 实测记录

- **日志文案修一处**：失败日志原用 `%v` 直接拼原因链，原因里带「空格+冒号」
  （`没有拿到任何可用直链：原生：该平台没有这一档音质`），拼完看起来就像消息正文，
  级别也跟着变灰，容易误读成成功。改为 `%q` 加引号后实测输出：
  `[BACKEND-DL] 失败：Taylor Swift - All Too Well（第 3 次尝试，耗时 0s）："没有拿到任何可用直链：原生：该平台没有这一档音质"`
  （`backend/pkg/backenddl/queue.go`）。
