# v2.24.18 — 在线更新「装完还是旧版本」+ 订阅开关可点 + WebP 封面

本版合并两批改动（同一待发布版本号，不各自占号）。

## 一、在线更新装完还是旧版本（用户 2026-11-01 报障）

用户原话：「在线更新有问题，下载完成后。刷新页面或者等一会儿，进来还是旧版本」。

### 根因：安装脚本的静默失败闭环

`backend/pkg/appupdate/script.go` 生成的 `apply-update.sh` 有两个独立缺陷，凑在一起正好是
一个**什么都没做、却报告成功**的闭环：

1. **验收判据错**：脚本只检查 `appcenter-cli status` 输出里有没有 `running` 字样就 `exit 0`。
2. **失败被吞**：`appcenter-cli uninstall "$PKG" >/dev/null 2>&1 || true` —— 卸载失败
   一点痕迹都不留。

于是：`uninstall` 静默失败（应用其实还在）→ `install-fpk` 对**已安装**应用是空操作
（HANDOVER §1.4.1 的真机实测结论：只打印 `[Info]Application [yinshu-ai] is installed.`
然后什么都不做）→ 旧进程还在 `running` → 脚本看到 `running` 就打印「更新完成」并
`exit 0`。

用户侧看到的就是「下载完成、提示安装成功、刷新还是旧版本」。

### 修法（`backend/pkg/appupdate/script.go`）

- `ScriptConfig` 新增 `Version` 字段，由 `Manager.Install()` 从 `DownloadState.Version`
  （下载时记录的目标版本）传进来，写进脚本的 `WANT_VERSION`。
- **按版本验收**：新增 `running_version()` 用 `curl` 打
  `http://127.0.0.1:8898/api/app/version` 取实际版本；`status` 说 running **且**版本等于
  `WANT_VERSION` 才 `exit 0`。版本对不上就继续等（最多 15 轮 × 2s，从 10 轮放宽），
  每轮把「实报版本 vs 期望版本」写进日志；等不到就 `exit 1` 并说明去应用中心手动装。
- **失败不再吞**：`uninstall` 失败先重试一次，再失败就 `log "卸载旧版失败…"` + `exit 1`；
  `install-fpk` 的失败与**完整输出**都写进日志（`install-fpk 输出：…`），失败即 `exit 1`。
- 没有目标版本号时明确打「警告：本次没有目标版本号，无法按版本验收」，不假装成功。
- **自查发现的一处自伤**：`running_version()` 里最初的 sed 写成了
  `s/.*"version":"([^"]*)".*/\1/p` —— BRE 模式下 `(` `)` 是**字面量**，版本号永远提取
  不出来，每一轮都会判「版本不对」，脚本必然超时失败（等于把「按版本验收」做成永远失败）。
  已改成 `\( \)`，并加两条测试把正则钉住：一条断言脚本里必须是转义括号，一条真的用
  `sh + sed` 跑一遍从真实响应串里提取 `2.24.18`。

### 顺带：安装日志可读（新增接口 + 界面）

`GET /api/app/update/install/log?lines=40`

- `backend/pkg/appupdate/manager.go`：新增 `InstallLogTail(maxLines)` 与 `InstallLogPath()`；
  `InstallResult` 增 `version` 字段。
- `backend/pkg/api/app_update.go`：新增 `HandleAppUpdateInstallLog`（只读，`ok=false` 表示
  还没有日志，不是 404）；`backend/pkg/api/routes.go` 登记路由；
  `backend/pkg/api/catalog.go` 补目录条目（`catalog_routes_test.go` 要求每条路由都在目录里）。
- `frontend/src/services/appUpdate.js`：新增 `installLog` / `installLogPath` ref 与
  `fetchInstallLog()`；`installUpdate()` 成功后顺带取一次；`resetForTests` 一并清空。
- `frontend/src/components/UpdateCard.vue`：新增可折叠的「安装日志」块，`onMounted` 时
  静默取一次。

为什么日志在 `/tmp` 里反而有用：安装脚本由独立会话（`setsid`）执行，应用会被
`uninstall` 掉再装回来，但 `/tmp/yinshu-update/install.log` 不会随之消失 —— 装完重启后
仍然能回看脚本到底做到哪一步。

### 新测试（`backend/pkg/appupdate/script_test.go`）

- `TestApplyScriptVerifiesVersionNotJustRunning`：脚本必须含 `WANT_VERSION`、`/api/app/version`、
  `if [ "$got" = "$WANT_VERSION" ]`、`继续等待`、`exit 1`；并反向断言**不再**存在
  「看到 running 就 exit 0」的老片段。
- `TestApplyScriptSurfacesUninstallAndInstallFailures`：反向断言 `uninstall … || true`
  已消失；`卸载旧版失败` / `install-fpk 失败` / `install-fpk 输出` 必须在脚本里。
- `TestApplyScriptWarnsWhenNoTargetVersion`：缺目标版本时必须写明「无法按版本验收」。
- `TestApplyScriptVersionSedIsBRE`：断言 sed 用的是 BRE 转义括号 `\( \)`，不是裸 `( )`。
- `TestApplyScriptVersionExtractionWorks`：用 `sh` 真跑一遍 `sed`，从真实
  `/api/app/version` 响应串里提取出 `2.24.18`（不依赖 curl）。
