# v2.24.17 — 补下载搜源与失败原因可见（issue #10-B / #11 剩余两条）

承接 v2.24.16（issue 审计 5 条修完）后用户 m02008「继续修」—— 当时报告的「未处理」两条：

1. 后台推送/补下载的自动搜源只搜 tx/wy，洛雪源不参与；后台渠道可用时自动补下载会整体跳过。
2. 队列里单条任务只显示一个错误码，看不到分渠道失败明细。

## 判定与修复对照

| 现象 | 判定 | 本轮 |
|---|---|---|
| 「11 个洛雪源全绿、补下载却全记没搜到」 | `pushEngine.js` 两处 `enqueueSongs(..., row.source === 'tx' ? 'tx' : 'wy', ...)` 写死平台，曲目自己的 `source` 被盖掉 | 修 |
| 「下回来的不是我要的那首」 | `list.find(s => s.source === platform) \|\| list[0]` —— 连歌名都不比 | 修 |
| 「失败里全是同一句没有可用直链」 | 搜不到平台 id 的歌仍被入队，只有原生渠道时必然失败 | 修（只在前台能按歌名搜时才交） |
| 「个别下载任务成功，歌单全部失败，这是废了吗」 | 失败徽标只有「下载失败」四个字，原因链只在 title 悬停里 | 修 |
| `autoFillPending` 在后台托管时整体跳过 | **保持**（见下「未改」） | 不改 |

## 改动

### 1. 补下载的搜源顺序（新增 `frontend/src/services/fillSource.js`）

- `fillPlatformOrder(track, rowSource)`：**曲目自己的平台优先**（`monitor.Track.source` / `missing[].source` 本来就带着最准的那个），其次订阅行 / 推送任务声明的平台；同一个平台只问一次。
  两个都不是已知平台（比如 `lx:全豆要` 这种洛雪伪源）时返回空数组，调用方改走聚合搜（`source=all`）。
- `pickSearchHit(list, track, preferPlatform)`：歌名归一后**必须完全相同**、两边都知道歌手时歌手要沾边、两边都知道时长时差不超过 `max(30s, 10%)`。以前的 `find(source===platform) || list[0]` 连歌名都不比，搜「晨钟暮鼓」拿到第一首别的歌也照下。
- `nameOnlyFallbackAllowed(channels)`：后台有 `lx` / `dl` 渠道时才允许「不带平台 id 地交上去让后台自己搜」。只有 `native` 时必须不交 —— 原生要平台 id，交上去只会排进队列再失败。
- `pushEngine.js` 两处调用点改成 `row.source || ''` 与 `task.provider === 'qq' ? 'tx' : task.provider === 'netease' ? 'wy' : ''`；`enqueueSongs` 内部按 `fillPlatformOrder` 逐个平台搜，命中即停；一个都没搜到时按 `nameOnlyFallbackAllowed` 决定「交上去」还是「如实记没搜到」。
- 顺带：`t.artist || t.singer` —— `missing[]` 条目里歌手字段叫 `artist`，`monitor.Track` 里叫 `artist`，但 `downloadManager` 的任务对象里是 `singer`，两种写法都认。

### 2. 失败原因摊开（新增 `frontend/src/services/failureBadge.js`）

- `explainFailure(raw)` 把后端拼好的原因链拆成 `{label, detail[]}`：
  `没有拿到任何可用直链：原生：该平台没有这一档音质；洛雪：服务端洛雪宿主未开启（默认关闭）`
  → label `平台无此档`，detail 两行。
- 徽标不再写死「下载失败」，改为 `briefLabel(first)`：认得出「平台无此档 / 平台不可播 / 洛雪宿主未开 / 写盘失败 / 超时 / 解析器未就绪 / 外挂池未启用 / 搜不到同一版 / 无可用直链 / 直链被拒 / 下回来的不是音频」，认不出就截前 12 字加 `…`。
- `DownloadQueuePanel.vue` 在失败行下面新增 `<ul>` 逐条列出 `detail`，只有失败任务且真有明细时出现。
- 为什么必需：后端早就把原因链写全了（`backenddl/fetch.go` 的 `planAttempts` 汇总），界面上却只有四个字 + title 悬停 —— 手机端根本没有悬停。

## 未改（本轮刻意不做）

- `autoFillPending()` 在 `backendDownload.subscriptionsManaged.value === true` 时仍然整体 return。这是「订阅不必开着网页」的开关：后端托管时它自己会入队（`ClientID = mon:...`，幂等），前端再补一遍会换一个 client_id 重复入队。要改得先定产品口径（谁负责补），不是纯 bug。
- `frontend/src/services/pushEngine.js` 的 `SearchAPI.search` 一次只问一个平台，多平台是串行问。歌单几十首时确实慢，但并发会打满音源服务（既有注释就是这么定的），本轮不动。
