### 三、修：音质下载下拉「选了不生效」（**v2.5.0 出厂就带着的 bug**）

- `writeQueue.js` 的写队列只登记了 `ids` / `enabled` / `ui` **三个键，漏了 `adq`**，
  而 `chartInject.js:139` 一直在调 `writes.adq(...)`：
  ```js
  export function setAutoDownloadQuality(q) {
    autoDownloadQuality.value = q || 'highest'   // ← 本地 ref 先变了，界面立刻显示新值
    return writes.adq(autoDownloadQuality.value) // ← TypeError: writes.adq is not a function
  }
  ```
  这个 Promise 没人 await，异常被静静吞掉 —— **界面上下拉明明变了，服务端一次都没写进去**，刷新就打回原样。
- 修法：`createWriteQueue` 补齐第四路（`pendingAdq` / `pump` 取值 / `while` 条件 / `adq()` 方法，
  四处必须一起加），并写清注释。
- 回归 4 条：`adq` 存在且真被写出去、空串（「跟随」）不被当成「没有待写」吃掉、
  四键互不干扰（没动的键必须是 `undefined`，后端选择性合并靠它）、
  **另加一条通用守卫** —— 读 `chartInject.js` 源码抓出所有 `writes.X(` 调用，逐个断言
  `typeof q[X] === 'function'`，这类「漏登记一个键」以后不会再静默。
- 实测：选「320K MP3」→ 真的发出 `POST /api/config {"auto_download_quality":"320k"}` →
  服务端读回 `320k` → 界面出现「已生效 12:39:36」回执（**以前这个回执永远不出现**）。

## 回合 115 —— 界面骨架重构 P0：导航 7 → 5 + 页内分段 + 统一反馈通道 + 设计令牌（v2.4.0）

**用户原话**：「请帮我重构整个页面的 ui、ux 和功能上的逻辑展示与互动」（m02162，一句话、无细节）。
处理方式：**先侦察出事实清单 → 写方案 → 让他拍板方向**，而不是自己猜一个方向写几千行。
方案落在 `docs/UI重构方案.md`（现状表 / 问题清单 / 容器三层规则 / IA 7→5 / 四件套 / 分期 P0–P3 / 验收 6 条）。
他拍了两处：范围 = **先做 P0**（看完效果再定 P1–P3），信息架构 = **7 → 5**。

**审计出来的四个结构性问题（都有证据，不是感觉）**：

1. **孤儿页**：`view-sources`（音源管理，`SourceManager.vue` 1,792 行）是个完整页面，却**不在 `navItems` 里** ——
   只能靠顶栏那个胶囊进；而那个胶囊同时在显示「当前音源是谁」并负责跳转，**一个控件干两件事**。
2. **三份并行清单**：导航项写在 `App.vue` 的 `navItems`、页面槽位写在模板、跳转散落在各组件里的
   `navigateTo('logs')` 这类字符串 —— 加一页要改三处，漏一处就是「页面存在但没人进得去」（第 1 条就是这么来的）。
3. **四套提示通道并存**：页脚文案 / 各页 `InlineNotice` / `appToast` 单槽位 / 原生 `alert`，
   同一件事三种说法 —— 用户上一轮的原话就是「提示太多了，看起来很挤」。
4. **裸值满地**：圆角/字号/间距/语义色直接写死在 56 个组件里（`rounded-xl` vs `rounded-[11px]`、
   `text-[12px]` vs `text-xs` …），视觉「不够统一」的根因在此。

**做法（关键取舍：P0 不动任何业务页面）**：

- **单一数据源** `frontend/src/services/navViews.js`：`VIEWS` 描述 5 个顶层视图（id / 名称 / 短名 / 图标名 /
  可选 `segments`），`resolveRoute()` 负责深链与向后兼容。
  `App.vue` 只剩 `NAV_ICONS` / `SEGMENT_ICONS` 两张 id→图标 表**按注册表渲染**。
- **「榜单并入发现」「日志+设置合成系统」用页内分段实现**（`components/SegmentedControl.vue`）——
  `SearchView.vue`(2,333 行) / `ChartManager.vue`(419) / `LogViewer.vue`(336) / `AppSettings.vue`(295)
  **一行都没动**，风险从「改 3,000+ 行业务页」降到「只改外壳」。分段两段都常驻（`v-show`）、
  首段懒挂载：来回切**不重建组件、不重发请求**（音乐类页面重建会丢搜索状态）。
- **统一反馈通道** `services/feedback.js` + `components/FeedbackHost.vue`（App.vue 挂一次）：
  队列 / 去重 / 超时 / 同时写 `appLog`；`fail()` 默认带「点一下看日志」。
  仍然保留 `alert` 作为最后兜底（没有监控台时）。
- **设计令牌**加进 `style.css` 的 `:root`（`--ys-*`）：**只登记已经在用的值**，不预造空令牌
  （空令牌就是下一批死代码，本轮刚清理过）。
- **`navigateTo('logs')` 这类老写法不用改**：`resolveRoute()` 把 `'logs'`/`'settings'` 解析成
  `{view:'system', segment:…}`、`'charts'` 解析成 `{view:'search', segment:'charts'}`。
- **HANDOVER 新增 §3.3.2**「导航壳与反馈通道」：写清「加一页要改哪三处」与容器三层规则
  （页面层 `PageShell` / 区块层卡片 / 条目层行 + 右侧动作区），避免下次又长出孤儿页。

**新增测试（三条，都是防「人肉清单不同步」的）** —— `frontend/src/services/navViews.test.mjs` 8 例：

## 回合 114 —— 手机端实测补测 + 实测工具两处失效修复

用户最初的问题里有一条是「有没有 UI 没有适配」。回合 109 建了 `.dev/measure-mobile.mjs`
（390×844 真机视口逐页实测），但它只覆盖当时存在的 10 个页面 —— **本轮新增的「设置」页不在里面**，
而它恰好是这轮改动最大的页面（五个分区）。

补测时又发现**这个工具自己已经失效**（两处，都与「页面破版」无关）：

1. **硬编码浏览器路径失效**：脚本 `spawn('/usr/local/bin/google-chrome')`，而这台 NAS 上现在
   **没有任何浏览器**（2026-10-15 实测：`google-chrome`/`chromium`/`firefox` 全无，
   也没有 playwright 下载的浏览器），第一次跑就 `spawn /usr/local/bin/google-chrome ENOENT` 崩。
   → 改为三级兜底：`CHROME_BIN` 显式指定 → `CDP_URL` **复用已经开着的浏览器**（不自己起）
   → 候选名单自动找（Linux/macOS 常见路径）；全找不到时打印人话并 `exit 1`，不再抛 ENOENT。
2. **误报「可横滑的一行」**：MEASURE 把「右侧超出视口」一律算成溢出，但 `overflow-x-auto`
   的 chip 行里、靠横滑才能看到的元素本就是设计意图 ——「本地音乐」的「+ 更多目录」
   每轮都被报成溢出（实测父容器 `cw=322 / sw=441`，是可滚动行）。
   → 新增 `clippedByScroll()`：祖先链上存在 `overflow-x: auto|scroll` 且确实可滚，就跳过。

**实测结果（390×844，本机浏览器，11 个页面）**：全部 `vw=390` / `docW=390` / **溢出 0 处**：

| 页面 | 溢出 | 页面 | 溢出 |
|---|---|---|---|
| 发现音乐 / 榜单管理 / 曲库管家 | 0 / 0 / 0 | 补全整理 / 自动下载记录 | 0 / 0 |
| 本地音乐 / 推送 / 下载 | 0 / 0 / 0 | 账号连接 / 日志 / **设置（新增页）** | 0 / 0 / 0 |

同时确认窄屏「一行两个元素」的布局真的生效：发现音乐、曲库管家、推送、下载、补全整理
均报出 `2col` 网格（回合 109 的两列改造未被本轮新页面破坏）。
