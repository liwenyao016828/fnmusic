### 一、先造一个组件，再改页面

改之前每个页面各写各的卡片，实测差异：

| | 圆角 | 标题字号 | 头部形态 |
|---|---|---|---|
| 发现页（主页，用户点名的标杆） | `rounded-[18px]` | 14px 加粗 | 图标方块 + 标题 + 一行副标题 |
| 设置页 | `rounded-xl` | 15px 半粗 | 纯文字 `h2` |
| 音源管理 | `rounded-2xl` | 12px 半粗 | 小图标 + 标题 + 右侧摘要 |
| 补全整理 | `rounded-xl` | 15px 半粗 | `h3` 标题 + `p` 说明 |

同一个应用里像三个应用的拼盘。所以第一步不是改页面，而是**把主页那套抽成组件**：
`frontend/src/components/SectionCard.vue`（77 行）。

```vue
<SectionCard :icon="Wand2" title="曲库目录" sub="下面四个动作都作用在这个目录" compact>
  ...
</SectionCard>
```

props：`title` / `sub` / `icon`（收 lucide **组件**而不是字符串 —— 传字符串会被 Vue 当成原生标签）/
`tone`（`brand` = 实心绿图标方块，只给「当前主任务」用；其余 `soft` 浅灰，**满屏实心绿等于没有重点**）/
`titleTitle` / `subTitle` / `compact` / `flush`。

组件注释里写死三条用法约定，免得以后又长歪：

- 副标题写不下就说明它该精简，而不是这张卡该变宽；
- 能悬浮解释的长文案走 `titleTitle`（或直接别写），别把三段话塞进头部；
- **卡内不要再嵌白底卡片** —— 内层用 `bg-gray-50/70` 这类浅底分区，白底嵌白底会让人分不清哪一层是边界（补全整理页以前就踩过）。

### 三、musicdl「报错」：那不是报错，是进度

截图里那条红条的来源是 `frontend/src/components/MusicDLSourcePanel.vue` 的 `load()`：
首次开启时**配置已写、总开关已亮，但 sidecar 正在建 venv + 装依赖（1–2 分钟）**，
8901 端口自然连不上 → `/sources` 失败 → `pageError.value = src.msg` 把
`dial tcp … connection refused` 原样贴成红色报错。

**新增 `shouldShowSourcesError(state)`**：

| sidecar state | 是否弹红条 | 理由 |
|---|---|---|
| `preparing` / `starting` | 否 | 正在装依赖 / 起进程，界面已有琥珀色「准备中」说同一件事 |
| `off` / `stopped` / `''` | 否 | 开关本来就是关的，没坏 |
| `ready` | 是 | 进程在却没响应 —— 真故障 |
| `failed` | 是 | 本次尝试已失败 |

顺带修两个相关缺陷：
1. `pageError` 现在**每轮 `load()` 开头先清空** —— 否则 sidecar 起来、源清单能读了之后，
   那条红条没人去擦，会一直挂在页面上。
2. 起进程期间**自动轮询**（`syncReadinessPolling()`，3 秒一次、上限约 100 次 ≈ 5 分钟）：
   起来后源清单自己就填上了。以前用户开着这一页等，得手动刷新才看得到「运行中」和 56 个源。
3. 修 `onUnmounted` **只停了试运行计时器、没停轮询**的泄漏（改成 `stopTimers(); stopReadinessPolling()`）。

### 四、全局多选 / 单选按钮统一（`style.css`）

实测全项目 `input[type=checkbox]` **20 处**，class 有 7 种变体：`accent-emerald-500`（×6）、
`accent-emerald-500 w-3.5 h-3.5`（×3）、`mt-0.5 shrink-0 accent-emerald-500`（×2）……
**其中 3 处裸着**（`TidyView.vue` 等，渲染成浏览器默认蓝）；
还有几处叠了 Tailwind forms 的 `text-emerald-500 rounded focus:ring-emerald-500` ——
那套要 `@tailwindcss/forms` 插件才生效，**本项目没装**，写了等于没写。
`<input type="radio">` 和 `role="radio"` 全项目 **0 处**（单选一律是卡片式 button）。

统一进 `frontend/src/style.css` 的 `@layer base`：

```css
input[type="checkbox"], input[type="radio"] {
  accent-color: #10b981;   /* emerald-500，与全站主色一致 */
  width: 1rem; height: 1rem;
  flex-shrink: 0; cursor: pointer; vertical-align: middle;
}
```

外加禁用态降透明度、`select:not([multiple])` 补圆角、文本类输入统一 `:focus-visible` 聚焦环。
**放 `@layer base` 是关键**：Tailwind 工具类在 `@layer utilities`，优先级更高，
所以 `w-3.5 h-3.5` 这类显式尺寸在局部仍能覆盖全局值。

实测：`getComputedStyle` → `accentColor: rgb(16, 185, 129)`、`w/h: 16px`。

### ⑦ musicdl 半成品 venv 不再卡死（**最值的修复**）

**事故现场**：dev 机器 `192.168.1.230` (debian) 上 `python3 -m venv <dir>` 报：

```
The virtual environment was not created successfully because ensurepip is not
available.  On Debian/Ubuntu systems, you need to install the python3-venv
package … apt install python3.11-venv
```

但它**失败时仍然留下目录**（`bin/python3 -> /usr/bin/python3` 符号链接 + `pyvenv.cfg`）。`backend/pkg/sidecar/sidecar.go` 的旧判据是 `os.Stat(m.venvPython())`，看到 symlink 存在就当成「已就绪」→ 跳过建 venv → 直接 pip install → `No module named pip`。**而「重试启动」每次都被同一条 Stat 短路**，永远修不好。

**修法**（`backend/pkg/sidecar/sidecar.go`）：
1. 新增 `venvUsable(ctx) bool`：要求 `pyvenv.cfg` 在 **且** venv 里真的能 `import pip`。
2. `ensureDeps`：
   - 半成品 venv → `os.RemoveAll` 重建（关键修复，让「重试启动」真的能再试一次）。
   - 建 venv 失败 → `os.RemoveAll` 残留目录再报错。
   - pip install 失败 → **不删 venv**（换网络重试就行，重建纯属浪费）。
3. `venvHint(out string) string`：识别 `ensurepip` / `python3-venv` / `python3.11-venv` / `No module named pip` / `No module named ensurepip` → 返回 `(这台机器没装 python3-venv：SSH 上去执行 \`sudo apt install python3-venv\`…)`，否则空。

**测试**（`backend/pkg/sidecar/sidecar_test.go` 5 条新增，共 18 条 PASS / 7.179s）：
- `TestVenvUsableRejectsHalfBuiltVenv` — 仅有 bin/python3 无 pyvenv.cfg → false；补 pyvenv.cfg → true。
- `TestVenvUsableRejectsVenvWithoutPip` — pyvenv.cfg 在但 `import pip` 失败 → false。
- `TestEnsureDepsRebuildsHalfBuiltVenv` — **关键回归**：标记匹配 + 半成品 venv → 必须重建并成功。
- `TestEnsureDepsCleansUpFailedVenv` — PythonPath 指向打 ensurepip 缺失报错的脚本 → 报错含 `python3-venv`，且 `os.Stat(venvDir)` 确认目录被清。
- `TestEnsureDepsKeepsVenvWhenPipInstallFails` — pip install 失败 → 报错含 `装依赖失败`，venv 目录**仍存在**、marker **未写**。

**环境修**（dev 机器）：
- `sudo -n true` 直接成功。
- `sudo apt install -y python3-venv python3-pip` → 装好 `python3.11-venv` / `python3-pip` / `python3-venv` / `python3-dev` / `python3.11-dev`。

## 回合 114 —— 手机端实测补测 + 实测工具两处失效修复

用户最初的问题里有一条是「有没有 UI 没有适配」。回合 109 建了 `.dev/measure-mobile.mjs`
（390×844 真机视口逐页实测），但它只覆盖当时存在的 10 个页面 —— **本轮新增的「设置」页不在里面**，
而它恰好是这轮改动最大的页面（五个分区）。

补测时又发现**这个工具自己已经失效**（两处，都与「页面破版」无关）：

1. **硬编码浏览器路径失效**：脚本 `spawn('/usr/local/bin/google-chrome')`，而这台 NAS 上现在
   **没有任何浏览器**（2026-10-15 实测：`google-chrome`/`chromium`/`firefox` 全无，
   也没有 playwright 下载的浏览器），第一次跑就 `spawn /usr/local/bin/google-chrome ENOENT` 崩。
   → 改为三级兜底：`CHROME_BIN` 显式指定 → `CDP_URL` **复用已经开着的浏览器**（不自己起）
   → 候选名单自动找（Linux/macOS 常见路径）；全找不到时打印人话并 `exit 1`，不再抛 ENOENT。
2. **误报「可横滑的一行」**：MEASURE 把「右侧超出视口」一律算成溢出，但 `overflow-x-auto`
   的 chip 行里、靠横滑才能看到的元素本就是设计意图 ——「本地音乐」的「+ 更多目录」
   每轮都被报成溢出（实测父容器 `cw=322 / sw=441`，是可滚动行）。
   → 新增 `clippedByScroll()`：祖先链上存在 `overflow-x: auto|scroll` 且确实可滚，就跳过。

**实测结果（390×844，本机浏览器，11 个页面）**：全部 `vw=390` / `docW=390` / **溢出 0 处**：

| 页面 | 溢出 | 页面 | 溢出 |
|---|---|---|---|
| 发现音乐 / 榜单管理 / 曲库管家 | 0 / 0 / 0 | 补全整理 / 自动下载记录 | 0 / 0 |
| 本地音乐 / 推送 / 下载 | 0 / 0 / 0 | 账号连接 / 日志 / **设置（新增页）** | 0 / 0 / 0 |

同时确认窄屏「一行两个元素」的布局真的生效：发现音乐、曲库管家、推送、下载、补全整理
均报出 `2col` 网格（回合 109 的两列改造未被本轮新页面破坏）。
